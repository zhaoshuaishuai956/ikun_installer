# 子项目创建规范提示词（复制即用）

> 用途：新建 NX 插件子项目时，把下方提示词发给 AI（或按检查清单自查），
> 确保子项目符合《子项目开发规范》并可被爱坤工具箱自动打包。
> 配套文档：`docs/子项目开发规范.md`（权威源：nx_dev_skill `08-子项目开发规范.md`）。

## 提示词（整段复制）

```
请帮我创建一个 NX 二次开发插件子项目「<插件功能一句话>」，严格遵循以下规范：

【第 0 步 · 强制问询】先问我：这个插件是否并入「爱坤工具箱」作为子项目？
得到答复后再继续，不要擅自决定。

【1 · 命名】英文名 = 仓库名 = 本地目录名 = dll 基名 = 插件 id（四者完全相同）：
- 全小写 snake_case，仅 a-z 0-9 _，长度 ≤ 28 字符
- 结构 `<对象>_<动作>` 或 `<对象>_<特征>`，见名知义；不用 nx_ / test_ / tmp_ 前缀

【2 · 仓库标准结构】创建以下文件：
- <插件名>.cpp / .hpp / .dlx      # 源码 + Block Styler 界面
- build.ps1                       # 编译脚本（模板）
- plugin.meta                     # UTF-8 key=value：name_cn（中文全称 4-10 字）、
                                  # icon_cn（图标名 ≤2 汉字）、category、in_ikun
- ikun-deploy.txt                 # 可选：每行一个 glob 的部署清单（缺省 *.dll *.dlx *.dat）
- README.md                       # What/Why/Run/Test
- CHANGELOG.md                    # 强制，格式见下
- .gitignore / .gitattributes     # LFS 只 track *.prt/*.bmp/*.ico；dll/dlx/dat 走普通 git 对象

【3 · CHANGELOG.md 格式（强制）】
爱坤工具箱 CI 每次打包时读取最新版本段写入 Release 发布说明，所以：
- 每个版本以 `## vX.Y.Z (YYYY-MM-DD)` 开头，版本号三段式 x.y.z（v 可省）
- 变更条目用 `- ` 列表；首条作为摘要，建议 `- **新增/修复/优化/变更**: 说明`

【4 · 编译与提交】
- dll 基名 = 工程英文名；中文界面文本注意编码坑（见 NX二次开发-踩坑总结.md）
- 提交遵循 Conventional Commits + Co-Authored-By

【5 · 并入爱坤工具箱（若第 0 步答「是」）】
- 在 ikun_installer 仓库 plugins.json 登记 { "repo": "<name>", "ref": "master", "icon": "<图标名>" }
- 在 DeployResources/startup/ 加菜单/图标：custom.men（GBK/ANSI 编码）+ ikun.rtb
- 在本插件仓库加 .gitea/workflows/notify-installer.yml（复制现有子项目的即可）
- plugin.meta 写 in_ikun=true

完成后逐项对照检查清单并告诉我结果。
```

## 完成检查清单

- [ ] 英文名合规（snake_case、≤28 字符、仓库名/目录名/dll 名/插件 id 四者同名）
- [ ] 标准文件齐全（含 CHANGELOG.md 且符合 §3 格式）
- [ ] plugin.meta 四项齐全（name_cn / icon_cn / category / in_ikun）
- [ ] 本地编译通过，dll 基名 = 工程名
- [ ] 已提交推送（Conventional Commits）
- [ ] 若并入爱坤：plugins.json + startup 菜单/图标 + notify-installer.yml 三处都已接好
- [ ] 触发一次子项目 push，确认爱坤工具箱 Release 的「子项目更新内容」出现本插件条目
