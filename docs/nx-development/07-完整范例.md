# 07 · 完整范例（一次任务从需求到交付的全程示范）

> 这是一个**示范剧本**（不是某次真实会话的日志），演示 [`05-执行协议.md`](05-执行协议.md) 的状态机怎么走。拿不准"下一步该干什么/输出成什么样"时，照本文的样子做。
> 所有代码事实均来自 [`templates/create_cuboid.*`](templates/)（已实测编译运行通过的模板）。

**任务设定**：用户说——"帮我做个插件，弹个对话框，输入长、宽、高，点确定在原点创建一个长方体。"

---

## S0 · 需求确认卡

> **Agent 发给用户：**

```
【需求确认卡】
1. 一句话目标：在 NX 建模模块做一个 Block Styler 对话框插件，输入长/宽/高，创建长方体。
2. 工程名（英文）：cuboid_lwh（默认，可改）  对话框标题：创建长方体（默认，可改）
3. 输入控件：
   长 | 表达式块 ExpressionBlock | 100 | 可键入公式
   宽 | 表达式块 ExpressionBlock | 50  | 同上
   高 | 表达式块 ExpressionBlock | 20  | 同上
4. 触发方式：NX 自带 [确定]/[应用]，不加内部按钮。
5. 点击后做什么：UF_MODL_create_block1 以绝对原点 (0,0,0) 为角点创建长方体
   —— 定位基准=绝对坐标系，所以会加 WcsGuard（防用户 WCS 转过导致长方体歪斜，03 §5）。
6. 不做什么：不做布尔运算、不选面、不记参数。
7. 验收标准：NX 部件导航器出现"块"特征，测量三边 = 输入的长宽高，且与绝对轴对齐。
请回复"确认"，或指出第几条要改。
```

> **用户**：第 3 条高度默认改成 25，其它确认。
> **Agent**：收到，高默认 25。开始执行。—— **关卡 G0 通过**（有明确确认，且修改点已复述）。

## S2 · 拷模板改写（列出每处改动）

拷 `templates/create_cuboid.{cpp,hpp,dlx}` + `templates/build.ps1` 到 `<工程根>/cuboid_lwh/`，改名为 `cuboid_lwh.{cpp,hpp,dlx}`。

> **Agent 发给用户的改动清单**（一次一个改动单元，全部列明）：

1. **改名连带 3 处**：`cuboid_lwh.cpp` 的 `#include "cuboid_lwh.hpp"`；`ufusr` 里拼 dlx 文件名的 `"\\cuboid_lwh.dlx"`；（类名 `CreateCuboid` 保留不改，不影响功能）。
2. **dlx**：模板里已有一个表达式块（id `DBL_LEN`）。把它整体改 id 为 `EXPR_L`、`Title` 改"长"、`Value`/`Formula` 改 100；再**复制该 `<Property>…</Property>` 子树两份**，分别改 id `EXPR_W`（宽，50）、`EXPR_H`（高，25）。不手写新 XML（04 §四）。
3. **hpp**：成员 `expr_len` 改名 `expr_l`，新增 `expr_w`、`expr_h`（都是 `ExpressionBlock*`）。
4. **cpp / init_cb**：`FindBlock("DBL_LEN")` 改 `FindBlock("EXPR_L")`，新增两行绑定 `EXPR_W` / `EXPR_H` ——**与 dlx 的 id 逐字一致**（三处同步：dlx/hpp/cpp）。
5. **cpp / createCuboid**：三个 `sprintf` 分别用 `expr_l->Value()` / `expr_w->Value()` / `expr_h->Value()`。
6. **cpp / WcsGuard**：模板已自带 `WcsGuard`（`createCuboid()` 开头，配 `#include <uf_csys.h>`），与需求卡第 5 条"绝对系定位"正好对上——按铁律 3 确认改写过程中**没有动它**。（若从别的骨架起步、没带 WcsGuard，此刻按 03 §5 抄一份补上。）

改动后关键代码（节选）：

```cpp
void CreateCuboid::init_cb()
{
    CompositeBlock* top = theDialog->TopBlock();          // TopBlock 返回 CompositeBlock*（04 §二.2）
    lbl_info = dynamic_cast<Label*>          (top->FindBlock("LBL_INFO"));
    expr_l   = dynamic_cast<ExpressionBlock*>(top->FindBlock("EXPR_L"));
    expr_w   = dynamic_cast<ExpressionBlock*>(top->FindBlock("EXPR_W"));
    expr_h   = dynamic_cast<ExpressionBlock*>(top->FindBlock("EXPR_H"));
}

void CreateCuboid::createCuboid()
{
    WcsGuard wcsGuard;                                    // 绝对系定位（03 §5 ★）
    double l = expr_l ? expr_l->Value() : 100.0;          // ExpressionBlock 直接 Value()，不走 PropertyList
    double w = expr_w ? expr_w->Value() : 50.0;
    double h = expr_h ? expr_h->Value() : 25.0;
    if (l <= 0.0 || w <= 0.0 || h <= 0.0) { /* 弹错误框, 同模板 */ return; }
    double org[3] = { 0.0, 0.0, 0.0 };
    char e1[32], e2[32], e3[32];
    sprintf(e1, "%.4f", l);  sprintf(e2, "%.4f", w);  sprintf(e3, "%.4f", h);
    char* edges[3] = { e1, e2, e3 };
    tag_t feat = NULL_TAG;
    int err = UF_MODL_create_block1(UF_NULLSIGN, org, edges, &feat);
    /* 弹框报告成功/失败, 同模板 */
}
```

**关卡 G2 通过**：4 文件齐，6 处改动逐条列出。

**如果报错了（两个示范分支，演示查表纪律）：**

- 分支 A：报 `LNK2019 无法解析的外部符号 ... BlockStyler ...` 一大串 → 抄关键字查 [`06`](06-报错决策表.md) 表 B 第一行 → 漏 `libnxopenuicpp.lib` → 在 build.ps1 的 link 库列表补上 → 重编（**第 1 次重试**）。
- 分支 B：点[应用]时弹 `属性类型不正确` → 查 06 表 D 第一行 → getter 与控件不匹配 → 对照 04 §三逐个核对读值写法 → 修正重编（**第 1 次重试**）。
- 任一分支若**同一报错第 2 次重试仍失败** → 停：把报错原文 + 两次已试方案发给用户（铁律 7），不做第 3 次。

## 本范例踩过的协议要点（复盘）

1. **需求卡值回票价**：用户看卡后当场改了默认高度——没有卡，这个偏差要到交付后才暴露。
2. **自查表第 7 条的意义**：本例模板已自带 WcsGuard，自查=确认没被改丢（铁律 3）；若从别的骨架起步没带它，这一条就是最后一道网——新建几何歪斜是"不报错但表现不对"里最难查的坑（06 表 E 第一行）。
3. **三处一致**是改控件的头号事故点：dlx 改了 id、cpp 忘了改 FindBlock，界面正常但读值永远是默认值（不报错、最难查）。改完立刻逐字核对。
4. **报错先查表再动手**，且**同一报错最多修 2 次**。
