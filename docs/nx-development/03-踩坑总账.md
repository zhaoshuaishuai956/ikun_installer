## 1. 中文编码
（最高频、最反复）

- **NXString 默认按 GBK 解** → 凡是把中文喂给控件（ListBox / 状态栏 / 下拉项 / `PropertyList::SetString`）一律 `NXString(text, NXString::UTF8)`，否则乱码。
- **枚举下拉项**：dlx 里写 `<Items>` 项在 NX1847 **常不填充**（连纯 ASCII 也可能空，中文必空）→ 必须在 `init_cb` 运行时 `enum->SetEnumMembers(std::vector<NXString>&)`（中文项传 UTF8）。**从一开始就这么写**，别等下拉空了才补。
- **dlx 标题**用 `Title` + `type="utfstring"`（mask=256 才显示）。别用 `type="string"` 的 Layout Label 装中文（运行时显示"无标题"，英文反而正常，所以易漏）。
- **对话框 / 组标题**：窗口标题在主组 `</item>` 之后单独一段 `hierarchy="UGS::Styler::DialogItem"` 的 Title(utfstring)；组标题用 `hierarchy="UGS::UICOMP_group"` 的 Title(mask=257)。

## 2. 控件读值

- **读值 getter 必须类型匹配**，否则运行时抛 NXException「属性类型不正确 / Incorrect property type」：

  | 控件 | C++ 类 | 读值 |
  |---|---|---|
  | 字符串 | StringBlock | `GetString("Value")` |
  | 双精度 | DoubleBlock | `GetDouble("Value")` |
  | 整数 | IntegerBlock（不是 IntBlock，头 `BlockStyler_IntegerBlock.hxx`）| `GetInteger("Value")` |
  | **枚举** | Enumeration | **`GetEnum("Value")`** → int 索引（用 GetInteger 必报错，最高频坑）|
  | 开关 | Toggle | `GetLogical("Value")` |
  | 表达式 | **ExpressionBlock** | **`b->Value()`**（已求值 double，不走 PropertyList）|

- **数值输入一律用 `ExpressionBlock`**（用户可填表达式 / 带单位），别用裸 DoubleBlock。手写 dlx 表达式块易缺属性致加载失败 → 从 NX 样例（如 `EditExpression`）提子树，改 `id`/`API Name`/`Value`/`Formula`/`Title`。
- **`TopBlock()` 返回 `CompositeBlock*`**（`FindBlock` 是它的成员，不是 UIBlock 的）→ `#include <NXOpen/BlockStyler_CompositeBlock.hxx>`。
- **选择类控件（面 / 点选）的显示标签走 `LabelString` 属性，不是 Title**。改这个才能让 "Specify Point" 等变中文。
- **点选块**：class `UICOMP_point`，读值 `GetProperties()->GetPoint("Point")` → `Point3d`(.X/.Y/.Z)。`(0,0,0)` 可当"未指定"判。
- **坐标系选择块（Specify CSYS，可同时拿原点+朝向）**：dlx class `UICOMP_coord_system`（**BlockStyler 样例里没有**，去 `UGOPEN/SNAP/Dialog/Specify Csys.dlx` 或 `LOCALIZATION/prc/gc_tools/.../gc_*_ui.dlx` 提整块改 id）。读值：`dynamic_cast<SpecifyCSYS*>(block)->GetSelectedObjects()`，空=未指定；取 `[0]->Tag()` → `UF_CSYS_ask_csys_info(csys,&mtx,org)` 拿原点 + `UF_CSYS_ask_matrix_values(mtx,m[9])` 拿轴（m[0..2]=X, m[3..5]=Y, m[6..8]=Z）。头 `BlockStyler_SpecifyCSYS.hxx` + `uf_csys.h`。
- **"必选"卡住应用** 真因是选择块的 `StepStatus`（0必选 / 1可选 / 2已满足），**不是 EnableOK**；必选步骤空着会禁用应用，OK 回调返 true 也压不住。
- **`init_cb` 里读 toggle 默认值常拿不到（返 false）/ SetShow 被随后渲染覆盖** → 初始显隐改 `theDialog->AddDialogShownHandler(...)`，在**对话框显示后**回调里再读再设。
- **NX 会记住上次对话框输入值**，覆盖 dlx 新默认——非 bug，改默认看不到先清缓存或换控件 id。
- `GetProperties()` 返回的 `PropertyList*` 用完必须 `delete`。
- 异常用 `catch (const NXException& ex)`，`ex.Message()` 取中文信息弹框。

## 2.x. 冗余确认按钮（勿重复 NX 自带按钮）

- **现象**：对话框里加了"创建/执行/确定"按钮,点它干的是 apply 的事 → NX 底部已有[确定]/[应用]/[取消],内部按钮纯冗余。
- **根因**：Block Styler 对话框自带三按钮（确定=应用+关闭;应用=执行+留在对话框;取消=退出），任何提交到模型的逻辑都应走 `apply_cb`/`ok_cb`。
- **解法**：不添加 `UICOMP_button` 做"提交型"操作；已有的改掉——删按钮 dlx 块、删 .hpp 成员、删 .cpp 绑定，逻辑正确放在 apply 里。内部按钮只用于不提交模型的辅助功能（预览/检查/计算/复制参数）。
- **参考**：`templates/create_cuboid.*` 是无按钮的正确示范。

# 3. 保留字 / 宏冲突

- `PI`、`max`、`min`、`CreateDialog` 与 NX 头 / windows.h 冲突：自定义常量别叫 `PI`（用 `kPi`）；含 `windows.h` 后 `#undef CreateDialog` / `#undef max` / `#undef min`。
- `far` / `near` 是保留字，不能当变量名。
- 含 Part 头后，BlockStyler 的 `Group` 要全限定 `NXOpen::BlockStyler::Group`（否则命名冲突）。

## 5. NXOpen / UF API（含 WCS 坑）

### ★ WCS≠绝对系 → 新建图元歪斜（务必先看）

- **`UF_MODL_*` 建模图元（`create_block1`/`create_cyl1`/拉伸等）按【当前 WCS】定位定向**，不是绝对系。用户 WCS 一旦相对绝对系旋转 / 平移，新建几何（底板、凸台…）就被带偏：**包不住、不平齐、整体歪一角**。
- 而零件用 `uf5945`/`uf5947` 变换、`UF_MODL_ask_face_props` 读取都走**绝对系**，所以零件不歪 → **症状只出现在"新建图元"上**，最难一眼看出根因。
- **解法 = WcsGuard（RAII）**：操作开头把 WCS 临时设为绝对系，离开（含异常）自动还原。

```cpp
#include <uf_csys.h>
struct WcsGuard {
    tag_t saved; bool ok;
    WcsGuard(): saved(NULL_TAG), ok(false) {
        if (UF_CSYS_ask_wcs(&saved)!=0) return;
        double m[9]={1,0,0, 0,1,0, 0,0,1}, o[3]={0,0,0}; tag_t mt=0, cs=0;
        if (UF_CSYS_create_matrix(m,&mt)==0 && UF_CSYS_create_temp_csys(o,mt,&cs)==0
            && UF_CSYS_set_wcs(cs)==0) ok=true;
    }
    ~WcsGuard(){ if(ok && saved!=NULL_TAG) UF_CSYS_set_wcs(saved); }
};
// run() 开头：  WcsGuard wcsGuard;
```

### 其它 API 坑

- `UF_EVAL_free(ev)` **按值传 ev**，不是指针。
- **坐标系裸建报 "Null tag not allowed"**：`CreateCoordinateSystem(origin,xDir,yDir)` 挂 MCS 即报。正解 `Xforms()->CreateXform(...)` → `CreateCoordinateSystem(xform, UpdateOptionAfterModeling)`。
- **复制+变换**：`uf5945`(绕轴(origin,dir)转 deg 出矩阵) / `uf5943`(平移出矩阵) / `uf5947`(应用，move_or_copy=2 复制 / =1 移动)；走绝对系。
- **取面信息**：`UF_MODL_ask_face_props`(中点 / 法向 / U,V 切向，绝对系)、`UF_MODL_ask_face_loops`(外环 type==1，内孔 type==2)、`UF_MODL_ask_face_body`(面→体)。
- **包围盒**：`UF_MODL_ask_bounding_box(obj, box[6])`，box=`{xmin,ymin,zmin,xmax,ymax,zmax}` 绝对系（头 `uf_modl_utilities.h`）。
- **图元创建**：`UF_MODL_create_block1(sign,corner[3],char* edge[3],&feat)`、`UF_MODL_create_cyl1(sign,origin[3],char* h,char* d,dir[3],&feat)`（尺寸都是字符串，可填表达式）；`UF_MODL_ask_feat_body(feat,&body)` 取体。
- **布尔**用显式 target+tool，别用自动求和（两体重叠会抓错体）。
- **特征编组** `create_set_of_feature` 对顺序敏感（全树差集遍历序≠时间序）→ 平铺，或每步立即记新特征。

> 模块专属的 API 坑（CAM 余量/后处理、PMI 标注等）见 [§8 CAM](#8-cam--后处理) 与 [§9 其它模块](#9-其它模块装配制图钣金pmi运动)。

## 6. 几何 / 算法

- **多零件必须共用同一坐标系**：各用各自局部坐标系算位置 → 落位飞远 / 交叉。若各面法向不同，则每件用自身底面坐标系提取轮廓、落位时**刚体映射到统一目标平面**（对齐法向→平面内转→平移）。
- **让结果矩形与绝对轴正交**：统一平面的 ex 取世界 X 在该平面的投影、ey=n×ex、n 吸附到最近绝对轴，别继承首件的任意 U 方向。
- **栅格排样**：真实多边形扫描填充成位图（保留凹形）→ 按 spacing/2 欧氏膨胀（膨胀半径 +1px、floor 改四舍五入，否则量化后实际间距偏小）→ uint64 行位与碰撞。凹形 / 去孔 / 间距 / 不重叠都是栅格法天然副产品。
- **BL 落底**：只从天际线往上找位会钻不进悬垂空腔 → 左下大空洞；改在 `[0, 天际线)` 段找空腔填洞。
- **逐件放置代价别含外包围盒面积**：会"对角散开 / 菱形空洞"。逐件用**纯左下贴合**，长宽比 / 面积目标交给外层宽度扫描选优。
- **取顶 / 取面**：对体打射线取"最高命中"会落到模具顶面 → 选实体时取**朝向那侧的最近面**。
- **刻字/字体工具设字高30实测仅21.6、字间距设0仍有约6mm默认间距** → 字形墨迹不填满em方框(汉字中心线满高~800em、Hershey大写720em),却按整em(1000)标定字高与前进宽,把字身上下/左右白边计入了尺寸 → **字高按字身满高标定 sc=字高/BODY_EM(≈800,ASCII大写归一到同值);排版按每字墨迹水平包围盒推进(墨迹左缘对齐笔位、前进=墨迹宽+最小间距),字间隙=用户值,设0紧贴**

## 7. 流程 / 协作

- **dll 用 `GetModuleHandleExA`+`GetModuleFileNameA` 从 dll 自身目录拼 dlx 绝对路径**，别硬编码中文路径；dll+dlx 同目录部署。
- **入口** `ufusr` / `ufusr_ask_unload` 必须 `extern "C" DllExport`（`DllExport` 在 uf_defs.h = `__declspec(dllexport)`）。`dumpbin /exports xxx.dll | findstr ufusr` 验证。
- **日志目录用纯 ASCII 路径**（如 `C:\xxx\logs`），中文路径 fopen 写不进。
- **dlx 若由生成器（如 `_gen_dlx.py`）拼**：改控件必重跑生成器再编译。外部工具可能回退 dlx、丢控件、LF↔CRLF → "界面缺控件"先核对 dlx 与生成器。
- **编译通过 ≠ dlx 可用**：cl/link 根本不碰 dlx，XML 断标签（手改/手拼控件块最易丢 `</PropertyList></item></Property>` 三段关闭）要到 NX 加载对话框才炸 → 改完 dlx 必须过一遍 XML 解析器校验；`build.ps1` 已内建（编译前校验目录下所有 .dlx，坏 XML 直接报错并指出常见根因）。
- **同一个 dlx，两个解析器结论矛盾**（Python 说合法、PowerShell 5.1 说非法，报「Name cannot begin with …」且引号疑似被吞）→ PS5.1 的 `Get-Content` 无 BOM 时按 ANSI 解码 UTF-8，中文尾字节（如"体"的 `93`）与后面的 `"` 组成一个 GBK 字，闭合引号被吃掉 → 解析/校验 XML **一律固定编码读**：`[xml][IO.File]::ReadAllText($f,[Text.Encoding]::UTF8)`（build.ps1 校验器已改）。通用法则：**解析器打架先查编码/BOM，别怀疑文件内容**。
- **多 AI / 工具交替开发**（互相看不到对方记忆）→ 以工程内开发文档 + 本仓库为准，先读再回写。

## 8. CAM / 后处理

> NXOpen CAM 二次开发（工序创建 / 刀路生成 / 后处理出 G 代码）。dll 骨架、编译、加载与建模插件完全一致（见 [`02-标准流程.md`](02-标准流程.md)），只是 `run()` 里换成 CAM API；链接需加 `libnxopencpp_cam.lib`。CAM 类/流程速查见 [`04-控件与读值速查.md`](04-控件与读值速查.md)。

- **铸造/加工余量设了不生效**：只在工序 `CutParameters()->WallStock/FloorStock` 设值，回读有值但刀路不按余量走 → 在 `WORKPIECE` 的 `PartGeometry()->CreateGeometrySet()` 上同时 `SetCustomPartOffset(true)`+`SetPartOffset(余量)`，再按需把工序余量清零或只留差值，避免重复留量。
- **后处理出空 G 代码 / 报刀路无效**：工序建好没生成刀路就后处理 → 后处理前必须先 `operation->GenerateToolPath()`（或对整组生成）；未生成的工序后处理为空。
- **后处理器名字对不上就抛异常**：`CAMSetup::Postprocess(ops, postName, outFile, units)` 的 `postName` 必须是 NX 已注册的后处理器名（`…\MACH\resource\postprocessor\*.tcl/.def` 里、或用户 .pui 里登记的），拼写/大小写不符即失败 → 先确认名字存在再传。
- **找不到工序/组的 tag**：CAM 对象在 `CAMSetup` 树里（`GetRoot()` + 遍历 / `CAMGroupCollection`），不在建模特征树 → 用 `part->CAMSetup()` 入口取，别拿 FeatureCollection 找。

## 9. 其它模块（装配 / 制图 / 钣金 / PMI / 运动 …）

> 非建模/CAM 的模块专属坑随遇随记。dll 骨架/编译/加载不变，差异只在 API 命名空间与链接库（见 [`01-环境与要求.md`](01-环境与要求.md) §3、[`04-控件与读值速查.md`](04-控件与读值速查.md)）。

- **PMI 标注**：标注平面别用 ModelView（尺寸会不在选定面）→ 自定义平面(CreateXform+UserDefined)；尺寸线 `InferRelativeToGeometry(false)`+`SetValue(pt)`；竖直翻侧靠 `LeaderOrientation`。链 `libnxopencpp_annotations.lib`。
- **装配**：组件几何在**各自组件部件**里，工作部件里拿不到子件体 → 遍历 `part->ComponentAssembly()->RootComponent()`，对组件用 `UF_ASSEM_ask_part_occurrence` / occurrence tag 取几何；坐标要按组件 occurrence 的变换换算到装配系。
