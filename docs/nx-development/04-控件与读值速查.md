## 一、环境与编译

- **NX 版本**：1847。SDK 在 `<UGII_ROOT_DIR 的父目录>\UGOPEN`（默认安装路径 `C:\Program Files\Siemens\NX 1847\UGOPEN`）。头文件 `uf*.h`、`NXOpen\*.hxx`，库 `*.lib` 都在这里。
- **编译器**：Visual Studio 2022（需"使用 C++ 的桌面开发"工作负载）。
- **三个必链库**（缺一不可，少了就是一堆 LNK2019 无法解析符号）：
  - `libufun.lib` —— UF_* C 函数
  - `libnxopencpp.lib` —— Session/UI/NXMessageBox 等核心
  - `libnxopenuicpp.lib` —— **BlockStyler 全家桶 + UI::CreateDialog**（最容易漏的就是它）
- **关键编译开关**：`/MD`（动态运行时，与 NX 一致）、`/EHsc`、`/utf-8`（让源码里的中文字符串正确编码）、`/D_CRT_SECURE_NO_WARNINGS`（压掉 sprintf 警告）。
- **C4275 警告**（std::exception 作 NXException 基类）是 NXOpen 头文件自带的，无害，忽略。
- **导出入口**：`ufusr` / `ufusr_ask_unload` 必须用 `extern "C" DllExport`（`DllExport` 宏在 `uf_defs.h` 里 = `__declspec(dllexport)`）。否则 NX 找不到入口。用 `dumpbin /exports xxx.dll | findstr ufusr` 可验证导出成功。

### 中文路径的构建陷阱（工程根含中文目录时）
- **不要**写 LF 换行的 `.bat` 去 `cd` 中文目录再调 `cl` —— cmd 按 GBK 解析 UTF-8 的中文字节会乱码，且 LF-only 的 bat 在 cmd 下解析行为异常。
- 磁盘若关闭了 8.3 短名，中文路径没有 ASCII 短名可回退。
- **正确做法**（build.ps1 已实现）：在 PowerShell 里 `cmd /c "vcvars64.bat && set"` 把编译环境导进当前会话，然后**直接调用 `cl` / `link`**（PowerShell 7 能正确把 Unicode 路径作为参数传给原生程序）。注意 PowerShell 工具的环境变量**不跨调用**，导入 vcvars 和编译必须在同一次调用里完成。

## 二、踩坑清单（务必先看）

1. **枚举读值用 `GetEnum("Value")`，不是 `GetInteger`。** 枚举的 Value 内部注册为 enum 类型，用 `GetInteger` 取会抛 `NXException`「用于属性名称的属性类型不正确 / Incorrect property type」。这是最高频的坑。
2. **`TopBlock()` 返回 `CompositeBlock*`**，`FindBlock` 是 `CompositeBlock` 的成员，不是 `UIBlock` 的。用 `UIBlock* top = theDialog->TopBlock();` 会编译报错"FindBlock 不是 UIBlock 的成员"。要 `#include <NXOpen/BlockStyler_CompositeBlock.hxx>` 并用 `CompositeBlock* top`。
3. **整数块类名是 `IntegerBlock`，头文件 `BlockStyler_IntegerBlock.hxx`**，不是 `IntBlock`。
4. **NX1847 的 Initialize 回调返回 `void`**（老版本返回 int）。
5. **每个 `GetProperties()` 返回的 `PropertyList*` 用完必须 `delete`**，否则内存泄漏。
6. **getter 类型必须匹配控件**，否则就是第 1 条那个"属性类型不正确"错误。对照表见下。
7. 异常用 `catch (const NXException& ex)` 捕获，`ex.Message()` 拿中文错误信息弹框。
8. **控件标题(label)显示中文必须用 `Title` 属性 + `type="utfstring"`，不能用 `type="string"` 的 Layout Label。** 写成 `<Property id="Title" mask="256" name="Title" type="utfstring" group="General::" sname="Label" value="中文" source="1" ClassID="UGS::UICOMP" hierarchy="UGS::UICOMP_<类型>"/>`。用 `type="string"` 的 Label 装中文，运行时控件标题会显示「无标题」（英文反而正常，所以容易漏）。双精度/整数/按钮/枚举/字符串的标题都走这个 Title。
9. **对话框窗口标题不是 `<Dialog title="...">` 属性**（那个是设计时的文件路径）。运行时标题要在主组 `</item>` 之后加一段对话框级 PropertyList，里面放一个 `hierarchy="UGS::Styler::DialogItem"` 的 `Title`(utfstring) 属性。组标题则是 `hierarchy="UGS::UICOMP_group"` 的 `Title`(mask="257")。样板见 `ejector_layout.dlx` 或 NX 自带 HoleCoordinates.dlx。
10. **`NXString(const char*)` 默认是 `Locale`(中文系统=GBK)，不是 UTF-8。** 你用 `/utf-8` 编译、源码里中文是 UTF-8 字节，直接 `NXString("中文")` 会被当 GBK 解 → 在 ListBox/状态栏等显示乱码。**凡是把中文喂给控件的 NXString，都要写 `NXString("中文", NXString::UTF8)`**。典型场景：`ListBox::SetListItems`、`PropertyList::SetString`、`Enumeration::SetEnumMembers`。
11. **枚举下拉项含中文时，别只靠 dlx 的 `stringarray`**（按 GBK 解会变空/乱码）。改在 `init` 里用 `Enumeration::SetEnumMembers(vector<NXString(...,UTF8)>)` 运行时设置。dlx 的 `Title`(utfstring) 标题不受影响、正常显示。
12. **动态显隐/使能控件用 `UIBlock::SetShow(bool)` / `SetEnable(bool)`。** 但**初始**显隐(尤其"开关默认值决定显隐"的场景)**不要只在 `init_cb` 里做**——`init_cb` 时机读控件的 dlx 默认值往往拿不到(返回 false)、SetShow 也可能被随后渲染覆盖。正确做法：`theDialog->AddDialogShownHandler(make_callback(this,&Cls::onShown))`，在**对话框显示后**的回调里再读开关、再 SetShow 一次。否则"默认勾选"启动时界面不切换、要手动拨一下才对。
13. **线性尺寸 `LinearDimension`(dlx `UICOMP_linear_dim`, 中文"线性尺寸"输入框)需要一个表达式对象才工作**：`init` 里 `wp->Expressions()->CreateSystemExpressionWithUnits("8", mmUnit)` → `dim->SetExpressionObject(e)` → `dim->SetValue(8.0)`；读值 `dim->Value()`。mm 单位 `wp->UnitCollection()->FindObject("MilliMeter")`。
14. **预览/临时几何全程走 UF 级**：`UF_CURVE_create_line` 建、`UF_OBJ_delete_object` 删。**绝不能 NXOpen 建(如 `Curves()->CreateLine`)再用 UF 删** → 重复释放、NX 崩溃("Attempt to free already free object")。颜色 `UF_OBJ_set_color(tag,186)`(186≈红)、线型 `UF_OBJ_set_font(tag,UF_OBJ_FONT_DASHED)`(虚线)、线宽 `UF_OBJ_set_line_width(tag,UF_OBJ_WIDTH_3)`(≈0.25mm)。

## 三、读值对照表

| 控件 | C++ 类 | dlx class | 读值 getter |
|------|--------|-----------|-------------|
| 标签 | `Label` | `UICOMP_label` | （无值，仅显示） |
| 字符串 | `StringBlock` | `UICOMP_string` | `GetString("Value")` → NXString |
| 双精度 | `DoubleBlock` | `UICOMP_double` | `GetDouble("Value")` |
| **表达式(推荐)** | `ExpressionBlock` | `UICOMP_expression` | **`b->Value()`** → double（直接调块方法，非 PropertyList） |
| 整数 | `IntegerBlock` | `UICOMP_integer` | `GetInteger("Value")` |
| 枚举 | `Enumeration` | `UICOMP_enum` | **`GetEnum("Value")`** → int（选中索引） |
| 开关 | `Toggle` | `UICOMP_toggle` | `GetLogical("Value")` → bool |
| 按钮 | `Button` | `UICOMP_button` | 在 `update_cb` 里 `if (block == btn) ...` |

枚举另有 `GetEnumAsString("Value")` 拿当前项文本。

## 四、dlx 控件 XML 片段

dlx 是 Block UI Styler 生成的 XML，但可手写。整体骨架（见 template/nx_demo.dlx）：根 `<Dialog>` → 一个 `<item class="UGS::UICOMP_group">`（折叠组）→ 其 `Members` 的 `ContainerItems` 里平铺各控件 `<Property>` 块。

**新增/删除控件**：在 `ContainerItems` 的 `</PropertyList>` 之前，按下面片段增删对应块即可。所有块的 `value="XXX"`（API Name）就是代码里 `FindBlock("XXX")` 用的 ID，必须大写下划线风格且唯一。改 `Label`/`Title` 的 `value` 改显示文字。

> 提示：每个块都保留一组"通用属性"（Visibility/Sensitivity/Group/Expanded/HideGroup/…）即可，可适当精简；NX 会用默认值补齐缺省项。下面给的是**精简到能稳定加载**的版本。

### 字符串 String
```xml

hierarchy="UGS::UICOMP_group" presentation="String">
```

### 双精度 Double
与 String 同构，把 `string`→`double`、`UICOMP_string`→`UICOMP_double`、`icon="styler_real"`，Value 用 `type="real" value="100.0"`。

### 整数 Integer
与 Double 同构，`UICOMP_integer`、`icon="styler_integer"`，Value 用 `type="integer" value="1"`。

### 表达式 Expression（**默认用它做数值输入**，支持公式/引用部件表达式）
**约定：凡是数值输入（尺寸、间距、角度、数量等）一律用表达式块 `UICOMP_expression`，不用 DoubleBlock。** 用户可直接键入数字或公式（如 `p0*2`、`50/3`）。
- 读值：`ExpressionBlock* b = dynamic_cast<ExpressionBlock*>(top->FindBlock("EXPR_X")); double v = b->Value();`（**直接调 `Value()`**，已是求值后的结果；不是走 PropertyList）。头文件 `BlockStyler_ExpressionBlock.hxx`。
- 默认值写在 dlx 的 `Value`(double) 与 `Formula`(utfstring) 两个属性里（保持一致）；标题用 `Title`(utfstring, mask=256)。
- `Dimensionality`(enum) `selected="-1"` + `HasUnitsMenu="False"` = 无单位框（最稳，按你代码自行解释 mm/度）。需要带单位再设 Dimensionality。
- **最稳的拿块方式**：从 NX 自带 `SampleNXOpenApplications/C++/CustomFeatures/BlockAndCylinder/BlockAndCylinderUI/BlockAndCylinderUI.dlx` 里提取一个 `class="UICOMP_expression"` 的完整 `<Property>…</Property>` 子树，把其中的块 id（如 `expression0`）整体改名，再改 `Title`/`Value`/`Formula` 三处即可。手写易缺属性导致加载失败。

## 五、常用 UF 建模函数

```cpp
// 长方体: corner 角点, edge_len 三边长(字符串)
UF_MODL_create_block1(UF_NULLSIGN, double corner[3], char* edge_len[3], tag_t* feat);
// 圆柱: origin 底面中心, height/diam 字符串, dir 轴向
UF_MODL_create_cyl1(UF_NULLSIGN, double origin[3], char* height, char* diam, double dir[3], tag_t* feat);
// 球: center 球心, diam 字符串
UF_MODL_create_sphere1(UF_NULLSIGN, double center[3], char* diam, tag_t* feat);
```
sign 取值：`UF_NULLSIGN` 新建 / `UF_POSITIVE` 求和 / `UF_NEGATIVE` 求差 / `UF_UNSIGNED` 求交。
尺寸都是**字符串**（可填表达式），用 `sprintf` 把 double 转进去。

## 六、在 NX 中运行

1. 打开 NX 1847，新建/打开一个**模型(.prt)** 文件，进入建模环境。
2. 菜单 **文件 → 执行 → NX Open…**，或快捷键 **Ctrl+U**，选择编译出的 `xxx.dll`。
3. 弹出对话框 → 填参数 → 应用/确定。
4. `ufusr_ask_unload` 返回 `UF_UNLOAD_IMMEDIATELY`，改完代码重新编译可直接再次 Ctrl+U 加载，无需重启 NX。

**dlx 找不到 / 加载失败**：模板按"dll 同目录同名 `.dlx`"自动定位——检查 dlx 是否与 dll **同名同目录**（如 `my_tool.dll` + `my_tool.dlx`）。

## 七、进阶：选择/几何/关联建模（顶针布局工具 ejector_layout 实战）

### 选择块的面规则（区域：种子面+边界面）
`UICOMP_face_select` 自带选择意图规则。区域规则（种子面+边界面→自动收集区域内所有面）：
- `FaceMethodMask`(sname `FaceRules`) `value="0xe7f"` 已含"区域"位（Region Faces=2）；
- 默认规则 `FaceMethod`(sname `DefaultFaceRules`) 的 `selected` 设区域选项索引（**1**=Region Faces）即可默认区域。
- 运行时 `getTags(sel)`(= `GetProperties()->GetTaggedObjectVector("SelectedObjects")`) 拿到收集到的全部面。

### 取几何信息（UF）
- `UF_MODL_ask_face_data(face,&type,pt,dir,box,&r,&rd,&nd)`：type 16=圆柱(pt=轴上点,dir=轴向,r=半径)/22=平面(pt=面上点,dir=法向); box=包围盒。
- `UF_MODL_ask_face_props(face,uv,pt,u1,v1,u2,v2,norm,radii)`：拿面在 (u,v) 处的 U/V 切向（建面内坐标系 X/Y 用）。
- `UF_MODL_ask_face_body(face,&body)`：面→体（"点任一面扩选整个体"）。
- `UF_MODL_ask_face_edges(face,&uf_list)`：面→所有边（`UF_MODL_ask_list_count/ask_list_item` 遍历，`UF_MODL_delete_list` 释放）。
- `UF_MODL_trace_a_ray(1,&body,origin,dir,xfIdentity,0,&n,&hits)`：对**体**打射线，`hits[i].hit_point/hit_face`；`UF_free(hits)`。多射线取最高命中=俯视取顶。

### 关联建模（建实体特征）
关联拉伸一个面的外轮廓成板：
1. `wp->Sections()->CreateSection(...)` + `wp->ScRuleFactory()->CreateRuleEdgeBoundary({face})`（取外轮廓，比手动过滤边稳）→ `sec->AddToSection(...)`；
2. `wp->Features()->CreateExtrudeBuilder()` → `SetSection` → `BooleanOperation()->SetType(...Create)` → `CreateDirection(face,SenseForward,...)` → `Limits()->StartExtend()/EndExtend()->Value()->SetRightHandSide("dist")` → `CommitFeature()`；取体 `dynamic_cast<Features::BodyFeature*>(feat)->GetBodies()`。
3. 偏置侧面（模脚内缩）：`CreateOffsetFaceBuilder` + `CreateRuleFaceDumb(sideFaces)` + `Distance()->SetRightHandSide("±foot")` → `Commit()`。
- **链接库要加** `libnxopencpp_features.lib`、`libnxopencpp_geometricutilities.lib`（在 build.ps1 的 link 行补上）。
- 需要的头：`Features_ExtrudeBuilder/OffsetFaceBuilder/BodyFeature/FeatureCollection`、`Section/SectionCollection`、`ScRuleFactory`、`EdgeBoundaryRule/FaceDumbRule/SelectionIntentRule`、`Direction(Collection)`、`GeometricUtilities_BooleanOperation/Extend`、`Body/Face`、`NXObjectManager`。

### dlx 由 python 生成器生成
本工程 dlx 是用 `_gen_dlx.py` 拼出来的（每控件一个函数：face/point/lindim/enum/int/toggle/label/button/listbox）。**改控件必须重跑生成器再编译**。注意：外部编辑器/工具可能把 dlx 回退或丢控件、把 LF 换 CRLF——"界面缺控件"先核对 dlx 与生成器是否一致。

## 八、CAM 与其它模块速查

### CAM（命名空间 `NXOpen::CAM`，链 `libnxopencpp_cam.lib`）
典型流程（工序 → 生成刀路 → 后处理出 G 代码）：
```cpp
NXOpen::CAM::CAMSetup* setup = workPart->CAMSetup();          // CAM 入口（不在特征树）
// 取/建 几何组(WORKPIECE/MCS)、刀具组、方法组：CAMSetup()->CAMGroupCollection()
// 建工序：setup->CAMOperationCollection()->Create(program, method, tool, geom, type, subtype, name)
op->GenerateToolPath(...);                                     // 后处理前必须先生成刀路，否则空
// 后处理：postName 必须是 NX 已注册的后处理器名
std::vector<NXOpen::CAM::CAMObject*> ops = { op };
setup->Postprocess(ops, postName, outputG代码文件, NXOpen::CAM::CAMSetup::OutputUnitsPostDefined);
```
余量、后处理空刀路、后处理器名不符等坑 → [`03`](03-踩坑总账.md) §8。
