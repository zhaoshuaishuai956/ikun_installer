# 05 · 执行协议（任何模型必读，能力越弱越要逐字执行）

> 本文件是**做 NX 二次开发任务时的行为协议**。01–04 告诉你"知识"，本文告诉你"纪律"。
> 它的设计目标：让一个能力一般的模型，靠**查表 + 照做 + 机器验证**，做出接近顶级模型的交付质量。
> **每次任务开始时读完本文（很短），全程遵守。其它文档按下面的状态机在需要时再读。**

---

## 一、八条铁律

违反任何一条，几乎必然返工。每条后括号里是它防住的事故。

1. **需求确认卡未经用户确认，不写任何代码。**（防：理解错需求，做完才发现方向全错）
2. **永不从零手写工程文件**：cpp/hpp/dlx/build.ps1 一律从 [`templates/`](templates/) 拷贝改写，且**把每一处改动列出来给用户看**。（防：自由发挥引入低级 bug）
3. **模板里看不懂的代码一行也不许删**——`#undef CreateDialog`、`WcsGuard`、`extern "C" DllExport`、`GetModuleFileNameA` 拼路径……每一行都是某个坑的疤痕。（防：自作聪明删掉保命代码）
4. **只使用在 01–04、templates/、NX 官方样例（`UGOPEN\SampleNXOpenApplications\`）里出现过的 API**。要用没出现过的 API，必须先向用户声明"此用法未经本知识库验证"再用。（防：编造不存在的 NXOpen 函数）
5. **一次只做一个改动单元，编译通过再做下一个。**（防：一次改十处，报错无法定位）
6. **报错 = 抄下报错关键字 → 先查 [`06-报错决策表.md`](06-报错决策表.md)，查不到再查 [`03-踩坑总账.md`](03-踩坑总账.md) 全文；禁止凭感觉改代码。**（防：瞎猜乱试）
7. **同一个报错连续修 2 次仍未解决 → 停下**，把"报错原文 + 已试过的方案"整理给用户，不要第 3 次尝试。（防：死循环烧时间烧钱）
8. **每一步以机器判据为准**：编译看退出码、导出看 dumpbin、加载看 NX 实际弹窗。禁止在机器判据出来前宣称"已完成"。（防：虚报成功）

## 二、状态机（每步有关卡，过不了不许进下一步）

```
S0 需求确认 → S1 预检 → S2 拷模板改写 → S3 编译前自查 → S4 编译 → S5 验证 → S6 交付
                                ↑______________ 报错: 查06修复(≤2次) ______________|
```

### S0 · 需求确认（治"理解错需求"的关卡）

把用户需求翻译成下面的**需求确认卡**发给用户，**用户回复确认前禁止写代码**。用户没说清的项，填上你建议的默认值并标注"（默认，可改）"。

```
【需求确认卡】
1. 一句话目标：在 NX <模块> 里做一个 <对话框/无界面> 插件，用于 <做什么>。
2. 工程名（英文）：<xxx>   对话框标题（中文）：<xxx>
3. 输入控件（每行一个）：
   标签 | 控件类型(对照 04 §三) | 默认值 | 说明
   （数值输入一律用 表达式块 ExpressionBlock）
4. 触发方式：NX 自带 [确定]/[应用]（默认。禁止添加"创建/执行"类内部按钮，见 03 §2.x）
5. 点击后做什么：创建/修改 <什么几何或对象>，定位基准 <绝对坐标系(默认,用WcsGuard)/当前WCS/选中对象>
6. 不做什么（边界）：<xxx>
7. 验收标准（用户如何判断成功）：<例：部件导航器出现"块"特征，尺寸 100×50×20>
请回复"确认"，或指出第几条要改。
```

**关卡 G0**：用户明确回复确认。需求简单或用户说"照示范来"时，卡照发，但默认值直接给全、别追问细节。

### S1 · 预检

读 [`01-环境与要求.md`](01-环境与要求.md) 文末预检清单逐条确认；读 [`03-踩坑总账.md`](03-踩坑总账.md) 的 9 个分类标题，说出本次任务会碰到其中哪几类。
**关卡 G1**：预检清单全过（环境不齐先跑 `templates/setup-nx-dev-env.ps1`）。

### S2 · 拷模板改写

按 [`02-标准流程.md`](02-标准流程.md) Step 2：拷 4 个文件改名 → 替换占位符 → 按需求卡增删控件。
**改控件必须三处同步**：dlx 的 API Name / hpp 成员 / cpp 的 FindBlock，ID 逐字一致。dlx 里新控件块**从模板或官方样例复制子树改 id**，不手写 XML。
**关卡 G2**：4 个文件齐；逐处列出你改了什么（给用户看的改动清单）。

### S3 · 编译前自查（治"基础代码问题"的关卡）

对照下表逐条自查，在回复里**逐条打勾**：

| # | 自查项 | 出处 |
|---|---|---|
| 1 | 枚举读值用 `GetEnum`（绝不是 GetInteger）？ | 03 §2 最高频坑 |
| 2 | 数值输入用 ExpressionBlock，读值 `b->Value()`？ | 03 §2 |
| 3 | 每个控件的 getter 与类型对照 04 §三核对过？ | 04 §三 |
| 4 | 控件 ID 三处（dlx/hpp/cpp）逐字一致？ | 02 Step 2 |
| 5 | 喂控件的中文都 `NXString(text, NXString::UTF8)`？枚举中文项走 `SetEnumMembers`？ | 03 §1 |
| 6 | `windows.h` 之后 `#undef CreateDialog/max/min` 还在？ | 03 §3 |
| 7 | 要新建几何的话，`run()`/apply 开头有 `WcsGuard`？ | 03 §5 ★ |
| 8 | 链接库 = 三必链 + 本模块追加库（对照 01 §3）？ | 01 §3 |
| 9 | `GetProperties()` 返回的 `PropertyList*` 用完 `delete`？ | 03 §2 |
| 10 | 没添加"创建/执行"类冗余按钮？ | 03 §2.x |

**关卡 G3**：10 条全过。

### S4 · 编译

```powershell
pwsh -ExecutionPolicy Bypass -File .\build.ps1
```

- 成功（exit 0，产出 dll）→ 进 S5，并把 **dll 完整路径**告诉用户。
- 报错 → 抄报错关键字查 [`06`](06-报错决策表.md) → 按表修 → 重编。**同一报错限 2 次**（铁律 7）。

### S5 · 验证

```powershell
dumpbin /exports <工程名>.dll | findstr ufusr
```

**关卡 G5**：看到 `ufusr` 和 `ufusr_ask_unload` 两个导出。

### S6 · 交付

告诉用户：① dll 路径 + NX 里 **Ctrl+U** 加载；② 界面有哪些控件、点[应用]会发生什么；③ **对照需求卡第 7 条验收标准**请用户验收；④ 移动目录需重编译的提醒。
运行期报错/表现不对 → 用户描述现象或发截图 → 查 06 运行期表。

## 四、对抗性审查（本协议为什么长这样）

- *"模型不读文档怎么办？"* → README 的新手提示词把"读 05 并全程执行"写成用户发出的第一条指令；SKILL/AGENTS 把它列为第 0 步。
- *"模型读了但不守关卡怎么办？"* → 关键关卡都是**机器判据**（编译退出码、dumpbin 输出、用户的"确认"回复），模型没法糊弄；纯自查类关卡（G3）要求逐条打勾输出，用户一眼能看出跳步。
- *"需求卡会不会过度打扰用户？"* → 卡里所有空缺项由模型填默认值，用户只需回一个"确认"；02 Step 1 本来就要求厘清这些项，卡只是把它变成不可跳过的格式。
- *"决策表(06)会不会和权威源(03)漂移？"* → 06 头部声明自己是 03 的索引视图；登记新坑时按维护仓的登记协议同步补 06 一行（有稳定报错关键字才补）。
- *"防死循环的 2 次上限会不会太保守？"* → 弱模型第 3 次尝试大概率还是错的，且会污染上下文；停下来问人/换强模型，期望成本更低。
