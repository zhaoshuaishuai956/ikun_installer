# 02 · 标准流程（零 → 可加载 dll）

> 这是已实测跑通的确定性流程。每步带命令。报错时回 [`03-踩坑总账.md`](03-踩坑总账.md) 对应分类定位。

> **模块无关**：不管做建模、CAM、装配、制图还是 PMI，dll 骨架、编译（`build.ps1`）、加载（Ctrl+U）这条流程**完全一致**；差异只在 `run()` 里调用的 API（建模 `UF_MODL_*`；CAM `part->CAMSetup()` + 工序 / `GenerateToolPath` / `Postprocess`；装配 `NXOpen::Assemblies`；制图/PMI `NXOpen::Annotations` …）和**追加的链接库**（见 [`01`](01-环境与要求.md) §3）。下面以带 Block Styler 界面的插件为主线，其它模块把 Step 2/建模那部分换成对应 API 即可。

## Step 0 · 先读坑账

通读 [`03-踩坑总账.md`](03-踩坑总账.md) 的分类标题（跨模块共性 7 类 + CAM/其它模块 2 类），标记本次必碰的几条（建模看 WCS、有控件看读值与编码、CAM 看余量/后处理）。**这一步省不得**——大部分返工来自没先读。

## Step 1 · 厘清需求

确认这几点，缺了就用括号默认值并说明：

- **⚠️ 新建插件先问一句**：「是否并入『爱坤工具箱』作为子项目？」——见 [`08-子项目开发规范.md`](08-子项目开发规范.md) §7 政策。是则按 §5 接入自动打包，否则建独立仓。
- **工程名**（英文，如 `my_dialog`）—— 文件名 / 类名前缀 / dll 名。**须遵命名规范**：全小写 `snake_case`、同名三位一体（仓库=目录=dll），见 [`08`](08-子项目开发规范.md) §1。不用驼峰/连字符/产品编号。
- **对话框标题**（中文友好）。
- **需要哪些控件**：标签 / 字符串 / 表达式(数值) / 整数 / 枚举(含选项) / 开关 / 按钮 / 选择(面·点·坐标系)。
  - **数值输入一律用「表达式块」**（`ExpressionBlock`），不用裸 `DoubleBlock`——支持用户键入公式 / 引用部件表达式，读值 `b->Value()`。
- **应用 / 确定时做什么**：建模？读参数？
  - **⚠️ 不要添加"创建/执行/确认"类内部按钮**——NX 对话框底部已有[确定]/[应用]/[取消]，任何"提交结果到模型"的操作都应走 apply_cb / ok_cb。内部按钮只保留"预览/检查/计算"等不提交结果的辅助功能。
- **输出目录**（默认 = 工程根下的 `<工程名>/`）。

需求简单或用户说"照示范来"时，别过度追问，直接用模板那套生成。

## Step 2 · 生成工程文件

从 [`templates/`](templates/) 拷四个文件到输出目录并改名为 `<工程名>.{cpp,hpp,dlx}` + `build.ps1`，然后改写：

1. **占位符替换**：cpp/hpp 注释里的 `{{NAME}}` → 工程名。**dlx 路径不用改**——模板运行时自动取"与 dll 同目录、同名的 `.dlx`"（`dlxPathBesideDll()`，坑账§7 的正解），改名/移动目录都无需动代码，只要保证 dll 和 dlx 同名同目录。
2. **cpp 的 `#include`** 改成 `<工程名>.hpp`。
3. **按需增删控件**——改动控件须**同时改三处**，三处的控件 ID 必须一致：
   - `.dlx` 的 XML 块（API Name 的 `value`）
   - `.hpp` 的成员指针
   - `.cpp` 的 `init_cb` 绑定 + `readValues` 读值（`FindBlock("ID")`）
   - 各控件 dlx 片段与正确的读值 getter 见 [`04-控件与读值速查.md`](04-控件与读值速查.md)。
   - **枚举读值用 `GetEnum`（不是 GetInteger）**，否则运行时报"属性类型不正确"。

dlx 用 UTF-8 保存，中文 label 直接写；但**枚举下拉项的中文要在 `init_cb` 里运行时 `SetEnumMembers`**（见坑账 §中文编码）。

## Step 3 · 编译

在输出目录运行：

```powershell
pwsh -ExecutionPolicy Bypass -File .\build.ps1
```

`build.ps1` 自动探测 VS/NX 路径、导入编译环境、`cl` 编译 + `link` 链接出 dll、清理副产物。
- **编译成功后必须把输出 `<工程名>.dll` 的完整路径告诉用户**，方便 NX Ctrl+U 加载。

> ⚠️ **不要**自己写 .bat 去 cd 中文目录编译（cmd 编码 + LF 换行会出错）。务必走 build.ps1。

报错速查（详见坑账 §链接库）：漏 `libnxopenuicpp.lib` / `IntBlock` 应为 `IntegerBlock` / `TopBlock()` 要用 `CompositeBlock*` 接。

## Step 4 · 验证并交付

```powershell
dumpbin /exports <工程名>.dll | findstr ufusr
```

确认导出了 `ufusr` 和 `ufusr_ask_unload`（dumpbin 需在导入了 vcvars 的环境里跑）。然后：

- 告诉用户：NX 打开模型 → **Ctrl+U** → 选 dll。
- 简述生成了哪些文件、界面控件、应用时行为。
- 提示：dlx 路径是运行时从 dll 位置推导的，移动/改名只需保证 **dll 与 dlx 同名同目录**，无需改代码重编译。

---

## 最小可加载插件骨架要点

1. `windows.h` 之后 `#undef CreateDialog / max / min`。
2. `ufusr` 里：`UF_initialize()` → 拼 dlx 路径（同目录）→ `new 对话框类(dlx); Show(); delete;` → `UF_terminate()`，全程 try/catch `NXException` 弹框。
3. 对话框类构造里 `theUI->CreateDialog(dlx)` + `AddInitializeHandler / AddApplyHandler / AddOkHandler / AddCancelHandler / AddUpdateHandler`。
4. `init_cb`（NX1847 返 void）里 `TopBlock()` → `FindBlock("ID")` 绑定各控件；枚举项在此 `SetEnumMembers`。
5. 控件 ID 三处（dlx / hpp / cpp）必须一致。
6. 要新建几何就在 `run()` 开头放 `WcsGuard`（见坑账 §API · WCS）。
