# 06 · 报错决策表（关键字 → 根因 → 修复动作）

> **用法**：抄下报错/异常/现象里的关键字 → 在下面对应阶段的表里找匹配行 → 按"修复动作"执行。
> 找不到匹配 → 查 [`03-踩坑总账.md`](03-踩坑总账.md) 全文；03 也没有 → **停下报告用户**（可能是新坑；解决后按维护仓的登记协议记进 03，有稳定关键字的同时补进本表）。
>
> **本表是 [`03-踩坑总账.md`](03-踩坑总账.md)（权威源）的索引视图**，只为"按报错查修法"而生；细节与原理以 03/04 为准（每行末列给出出处）。

## A. 编译期（cl 报 C 系列错误）

| 报错关键字 | 根因 | 修复动作 | 出处 |
|---|---|---|---|
| `C2059` 满屏语法错误 / 无法识别的字符 | 编译时没加 `/utf-8`，cl 按 GBK 读 UTF-8 中文注释 | 用 `build.ps1` 编译（已带 `/utf-8`）；确认源码为 UTF-8 | 01 §4 |
| `C2065` `IntBlock` 未声明 | 类名记错，整数块是 `IntegerBlock` | 改为 `IntegerBlock`，头 `BlockStyler_IntegerBlock.hxx` | 04 §二.3 |
| `FindBlock` 不是 `UIBlock` 的成员 | `TopBlock()` 返回 `CompositeBlock*` 而非 `UIBlock*` | 用 `CompositeBlock* top` 接，`#include <NXOpen/BlockStyler_CompositeBlock.hxx>` | 04 §二.2 |
| `CreateDialog` 相关的诡异重定义/找不到 | `windows.h` 的宏把它替换掉了 | `windows.h` 之后 `#undef CreateDialog`（`max`/`min` 同理） | 03 §3 |
| `PI` 重定义 | NX 头里已有 `PI` | 自定义常量改名（如 `kPi`） | 03 §3 |
| `far` / `near` 处语法错误 | 是保留字，不能做变量名 | 改变量名 | 03 §3 |
| `Group` 不明确 / 二义性 | 含 Part 头后与 BlockStyler::Group 冲突 | 全限定 `NXOpen::BlockStyler::Group` | 03 §3 |
| 无法打开包括文件 `uf.h` / `*.hxx` | SDK include 路径不对 | 确认 NX 已装、`UGII_ROOT_DIR` 已设；用 `build.ps1`（自动探测） | 01 §1 |
| `'cl' 不是内部或外部命令` | vcvars 环境未导入，或导入与编译不在同一次调用 | 一律走 `build.ps1`（`cmd /c "call vcvars64.bat && cl ..."` 同调用完成） | 01 §4 |
| `vswhere` not recognized | 无害 | 忽略，cl 仍能跑 | 01 §4 |
| `C4275`（std::exception 基类）警告 | NXOpen 头自带 | 无害，忽略 | 01 §4 |

## B. 链接期（LNK 系列）

| 报错关键字 | 根因 | 修复动作 | 出处 |
|---|---|---|---|
| `LNK2019` 一大堆，符号含 `BlockStyler` / `CreateDialog` | **漏了 `libnxopenuicpp.lib`（最高频）** | link 行加上它 | 01 §3 |
| `LNK2019` 符号含 `UF_`（C 函数） | 漏 `libufun.lib` | 加 `libufun.lib` | 01 §3 |
| `LNK2019` 符号含 `Session` / `NXMessageBox` / `UI` | 漏 `libnxopencpp.lib` | 加 `libnxopencpp.lib` | 01 §3 |
| `LNK2019` 符号含 `NXOpen::CAM` | 漏 CAM 库 | 加 `libnxopencpp_cam.lib` | 01 §3 |
| `LNK2019` 符号含 `Annotations` | 漏标注库 | 加 `libnxopencpp_annotations.lib` | 01 §3 |
| `LNK2019` 符号含 `Assemblies` | 漏装配库 | 加 `libnxopencpp_assemblies.lib` | 01 §3 |
| `LNK2019` 符号含 `Drafting` | 漏制图库 | 加 `libnxopencpp_drafting.lib` | 01 §3 |
| `LNK2019` 符号含 `Features`（拉伸/偏置等建模特征类） | 漏特征库 | 加 `libnxopencpp_features.lib`（几何工具类再加 `libnxopencpp_geometricutilities.lib`） | 04 §七 |
| `LNK2019` 符号含 `UF_UI`（选择/specify） | 漏交互库 | 加 `libugopenint.lib` | 01 §3 |

> 规律：`LNK2019 且符号名含某模块类名` → 九成是漏了 `libnxopencpp_<模块>.lib`（01 §3 有全表）。

## C. 加载期（Ctrl+U 后异常）

| 现象 | 根因 | 修复动作 | 出处 |
|---|---|---|---|
| Ctrl+U 选了 dll 没反应 / 报找不到入口 | `ufusr` / `ufusr_ask_unload` 没用 `extern "C" DllExport` 导出 | 按模板写法导出；`dumpbin /exports xxx.dll \| findstr ufusr` 验证 | 03 §7 |
| 报 dlx 找不到 / 对话框弹不出 | dlx 路径不对，或 dll 与 dlx 不在同一目录 | dll+dlx 同目录部署；cpp 用 `GetModuleFileNameA` 从 dll 自身目录拼路径（模板已带，别改坏） | 03 §7 |
| dlx 加载失败（尤其含手写表达式块时） | 手写 XML 缺属性 | 别手写：从模板/官方样例（如 `BlockAndCylinderUI.dlx`）提完整 `<Property>` 子树改 id | 04 §四 |
| **编译明明过了**，NX 加载对话框时才炸 / 报 XML 解析错 | dlx 断标签——手改控件块最易丢 `</PropertyList></item></Property>` 三段关闭；cl/link 根本不碰 dlx | 改完 dlx 重跑 `build.ps1`（已内建编译前 XML 校验，坏 XML 直接报错并指出常见根因） | 03 §7 |
| 同一个 dlx，两个解析器结论矛盾（如 Python 合法 / PowerShell 非法，报 `Name cannot begin with …`） | 解析器编码假设不同：PS5.1 无 BOM 时按 ANSI 读 UTF-8 中文，闭合引号被吞 | 更新到已固定 UTF-8 读的 `build.ps1`；通用法则：解析器打架先查编码/BOM，文件多半没坏 | 03 §7 |
| 换了目录后插件失灵 | dlx 绝对路径写死在 cpp 里 | 模板的"自身目录拼路径"写法天然免疫；若曾硬编码，改回模板写法重编 | 02 Step 4 |

## D. 运行期（点应用后报错 / 崩溃）

| 报错关键字 / 现象 | 根因 | 修复动作 | 出处 |
|---|---|---|---|
| `属性类型不正确` / `Incorrect property type` | 读值 getter 与控件类型不匹配（**最高频：枚举用了 GetInteger**） | 对照 04 §三读值表逐一核对；枚举一律 `GetEnum("Value")` | 03 §2 |
| `Null tag not allowed`（建坐标系时） | `CreateCoordinateSystem(origin,xDir,yDir)` 裸建挂 MCS | 改 `Xforms()->CreateXform(...)` → `CreateCoordinateSystem(xform, UpdateOptionAfterModeling)` | 03 §5 |
| NX 崩溃 `Attempt to free already free object` | NXOpen 建的对象用 UF 删（或反之），重复释放 | 预览/临时几何全程走 UF：`UF_CURVE_create_line` 建、`UF_OBJ_delete_object` 删 | 04 §二.14 |
| 点[应用]没反应，按钮是灰的 | 选择类控件 `StepStatus` 必选未满足（不是 EnableOK 的事） | 让用户完成必选步骤，或把该步 `StepStatus` 改可选 | 03 §2 |
| 抛 NXException 弹窗（其它信息） | 各异 | `catch (const NXException& ex)` 拿 `ex.Message()` 中文信息，按信息再查本表/03 | 03 §2 |

## E. 不报错但表现不对（最阴险的一类）

| 现象 | 根因 | 修复动作 | 出处 |
|---|---|---|---|
| **新建的几何歪斜 / 位置不对**（零件本身正常） | `UF_MODL_*` 按当前 WCS 定位，用户 WCS 转过 | `run()`/apply 开头加 `WcsGuard`（代码在 03 §5，直接抄） | 03 §5 ★ |
| 界面中文乱码（ListBox/状态栏/下拉） | `NXString` 默认按 GBK 解 | 一律 `NXString(text, NXString::UTF8)` | 03 §1 |
| 枚举下拉是空的 | dlx 的 `<Items>` 在 NX1847 常不填充 | `init_cb` 里 `SetEnumMembers(vector<NXString(...,UTF8)>)` 运行时设置 | 03 §1 |
| 控件标题显示"无标题"（英文却正常） | 用了 `type="string"` 的 Layout Label 装中文 | 改 `Title` 属性 + `type="utfstring"`（mask=256） | 03 §1 |
| 改了 dlx 默认值，界面还是旧值 | NX 记住上次对话框输入（非 bug） | 清缓存或换控件 id 再验证 | 03 §2 |
| "默认勾选"启动时界面不切换，拨一下才对 | `init_cb` 时机读不到默认值 / SetShow 被覆盖 | 初始显隐移到 `AddDialogShownHandler` 回调里做 | 03 §2 |
| 日志文件死活写不出来 | 中文路径 fopen 失败 | 日志目录用纯 ASCII 路径 | 03 §7 |
| 界面缺控件（明明加了） | dlx 由生成器生成，改了没重跑；或外部工具回退了 dlx | 重跑生成器再编译；核对 dlx 与生成器一致 | 03 §7 |
| 布尔求和抓错体 | 用了自动求和，两体重叠时抓错 | 显式指定 target+tool | 03 §5 |
| **CAM：余量设了不生效** | 只在工序 CutParameters 设了 | 在 WORKPIECE 的 `PartGeometry()->CreateGeometrySet()` 上 `SetCustomPartOffset(true)`+`SetPartOffset(余量)` | 03 §8 |
| **CAM：后处理出空 G 代码** | 没先生成刀路 | 后处理前先 `operation->GenerateToolPath()` | 03 §8 |
| **CAM：Postprocess 抛异常** | 后处理器名不是 NX 已注册名 | 核对 `…\MACH\resource\postprocessor\` 下登记名，拼写大小写一致 | 03 §8 |
| CAM：找不到工序/组 | 在建模特征树里找 CAM 对象 | 走 `part->CAMSetup()` 树（`GetRoot()`/`CAMGroupCollection`） | 03 §8 |
| PMI：尺寸不在选定面上 | 标注平面用了 ModelView | 自定义平面（CreateXform+UserDefined）；详见 03 §9 | 03 §9 |
| 装配：工作部件里拿不到子件体 | 组件几何在各自组件部件里 | 遍历 `RootComponent()`，用 occurrence tag 取几何并换算坐标 | 03 §9 |
