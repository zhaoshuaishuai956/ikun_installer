# 爱坤工具箱图标设计语言（紫色技术图标版）

版本：v1.1 · 日期：2026-09-01 · 状态：**已批准并用于在册业务插件**

> 定位与优先级：本文件只定义图标的**视觉设计语言**，是《NX二次开发权威规范》§4.1「菜单与 Ribbon 图标」的**下位细则**，不另立工程标准。

## 1. 设计哲学（第一性原理）

1. **对象中性，动作着紫**。模板板/实体是「对象」，用近中性的浅紫白顶面 + 浅紫灰侧面表达；**被操作的东西（顶针、凸台、孔、尺寸、箭头、齿轮、文本行）才是亮紫焦点**。这与 NX 原生特征图标「中性实体 + 一块作用色面」同构，仅把作用色由原生橙/青换成主题紫。
2. **轻，而不是淡**。轻来自「面浅」，不来自「线淡」：描边用清晰的紫味深灰，浅色面靠清晰深线勾边，小尺寸才不发虚。
3. **立体但扁平、且合规**。用斜等轴三面表达体积，但**三面为同色系平涂、无渐变背景、无阴影、无照片质感**，满足 §4.1「扁平技术图标、禁止渐变背景/阴影」。
4. **功能可辨优先于装饰**。每枚先确定「对象 + 动作」两要素再选元件；32px 下一眼读出命令类型，主体居中、留足边距。
5. **一套语法、克制用色**。只用第 4 节有限色板，不引入额外色相；紫色只靠明度分层。

## 2. 形态语言：斜等轴三面实体

### 2.1 投影
- 等轴向量 `U=(+0.866,+0.5)`、`V=(-0.866,+0.5)`（与水平各成 ±30°），`W=(0,+1)` 竖直向下。
- 世界坐标 `(u,v,w)` → 屏幕：`x=ox+(u-v)*0.866*S`，`y=oy+(u+v)*0.5*S+w`。
- 32×32 画布：板类 `S≈8.2~8.4`、顶面中心 `(16,10~12)`、板厚 `h≈3.2~3.4`；厚实体（工具箱）`S≈7.4、h≈8.4`。

### 2.2 三面平涂规则（固定、纯色无渐变）
| 面 | 朝向 | 平涂色 | 语义 |
|---|---|---|---|
| 顶面 | 朝上 | `#EDE6FC`（浅紫白） | 对象受光面，近中性 |
| 右前面 u=+1 | 朝右前、最迎观众 | `#9061F0`（亮紫） | **作用面 / 结果面** |
| 左前面 v=+1 | 朝左前 | `#B6A6E0`（浅紫灰） | 体积/厚度，保持浅 |
| 所有棱边 | — | `#433A5E` 紫味深灰，宽 1.3 | 清晰细描边，不用纯黑 |

> 薄模板板的右前作用面较窄时，「亮紫焦点」由板上功能特征（顶针/凸台/孔/尺寸/字符）承担，语义不变。
> 后层叠板（批量）用更淡的 `#E4D9F8 / #C3B0F2 / #C2B2E4`，先画、被前板遮挡。

### 2.3 非实体的系统类图标
环形（检查更新）、信息球（关于）这类无实体对象的命令，允许用正对屏幕的符号，但配色、描边、圆角与全套一致（亮紫 + 紫灰边），保证统一。

## 3. 网格与尺寸（入库规格服从 §4.1）

- 统一在 **32×32** 矢量画布绘制；安全边距 ≥2px，主体视觉占比约 70%，居中。
- **入库/部署唯一位图规格：32×32、24 位、白底 BMP**（§4.1 Ribbon LARGE_IMAGE 源图；NX 自动向下缩放供中/小图标）。单文件 54+32·32·3 = **3126 字节**，与现网资源一致、可过 G5c。
- **不产出、不入库 16×16 / 48×48 位图**，也不新增 24×24（§4.1：禁止把 24×24 放大成大图标；遗留 24×24 仅迁移期保留并由 G5c 报警）。设计阶段的多尺寸预览仅用于评审，不进 `DeployResources/startup/`。
- 圆角：板/块外圆角 r≈3，元件 r≈1~1.5，线帽/交点 round。

## 4. 色彩系统（平涂色板，全套唯一用色）

| 角色 | 色值 | 用途 |
|---|---|---|
| 描边 STK | `#433A5E` | 全部棱边/轮廓，紫味深灰（非纯黑） |
| 顶面 TOP | `#EDE6FC` | 顶面受光面 |
| 侧面 SIDE | `#B6A6E0` | 左前面体积 |
| 作用紫 PUR | `#9061F0` | 作用面与功能特征主体 |
| 柱顶 CAP | `#C9B6FA` | 顶针/凸台柱顶受光 |
| 强调 ACC | `#7C57E5` | 尺寸线、箭头、环形、点阵等动作符号 |
| 强调深 ACC_D | `#6A44D6` | 箭头尖端/孔心，极小面积 |
| 白底/白形 | `#FFFFFF` | 画布底、孔心、信息 i、字符 |
| 后层三件套 | `#E4D9F8 / #C3B0F2 / #C2B2E4` | 叠摞/批量的后板 |

用色规则：
- **单图标亮紫（PUR+ACC）面积建议 25%~45%**，其余为浅紫白/浅紫灰；严禁超过 60%（即「铺满高饱和紫块」的旧错误）。
- 不用纯黑、不用高饱和暗紫（如 `#5B21B6/#4C1D95`）铺底；不使用渐变背景、外发光、硬投影。
- 为浅色 Ribbon/菜单设计（NX 默认主题）。

## 5. 元件库

绘制脚本见 `assets/`（SVG 源由参数化元件生成）。所有图标复用同一套元件，不另造画法：

| 元件 | 作用 | 要点 |
|---|---|---|
| block / back | 斜等轴三面板/块、后层叠板 | 纯色三面 + STK 描边 |
| cyl | 面上向上凸起的圆柱（顶针/凸台） | 世界坐标定位，柱身 PUR、柱顶 CAP |
| hole | 面上凹孔 | 浅紫椭圆环 + 白心 |
| gear | 正屏齿轮（批量/处理动作） | 8 齿，PUR + 白轴 |
| arrow | 正屏实心箭头（动作方向） | 任意角度，ACC |
| cross | 面上定位十字 | ACC_D |
| wline / wquad | 等轴面内的线/平行四边形（文本行、图纸折角） | 世界坐标 |
| ell/circ/rrect/line/poly | 基础形 | 屏幕坐标 |

组合范式：`block`（对象）→ 顶面世界坐标布置 `cyl/hole/wquad`（特征，着 PUR）→ 按需叠加正屏 `arrow/gear`（动作，ACC）。

## 7. 工程导出与发布合规（强制）

1. 链路：参数化 SVG（32 画布）→ 栅格化透明 PNG（中间产物）→ **合成白底、导出 32×32、24 位 BMP**。
2. 位图必须满足 G5c：`BM` 签名、planes=1、**bits=24**、宽高 32；白底（§4.1 统一白色底）。**不要提交 32 位带 alpha 的 BMP 到 startup**（G5c 会判失败）；带透明的 PNG/SVG 仅作设计资产留在 `docs/design/assets/`。
3. 命名 `ikun_<repo>.bmp`（updater 固定 `ikun_tools.bmp`），只放 `DeployResources/startup/`；更新既有图标**不得改 BUTTON、LABEL、ACTIONS**（§4.1）。
4. `ci/gen-icons.sh` 只是为**缺失**图标生成 24×24 白底橙字占位的兜底；正式图标一律按本语言手工/脚本产出 32×32 24 位，不依赖占位。
5. 提交前：先在 100% 原尺寸做视觉检查（§4.1），再运行 `python ci/check_consistency.py`，G5c/G5f 无新增失败；图标风格或验证规则变更按 §11 留审查报告。

## 8. 宜 / 忌

- **宜**：浅紫白面 + 浅紫灰侧面立对象；亮紫只给作用面/特征；紫味深灰细边；纯色平涂、白底、居中留边、32px 可辨。
- **忌**：高饱和紫铺满；深紫/近黑粗描边；深色挤出厚度、硬投影、渐变或照片背景；多种强调色混用；为「轻」把线弄淡导致发虚；提交 24×24 放大图或 32 位 alpha BMP 到 startup。

## 9. 新增 / 重绘一枚图标的 SOP

1. 明确「对象 + 动作」，先确认该图标对应的 `repo` 与四字中文名（§3），文件名固定 `ikun_<repo>.bmp`。
2. 用第 5 节元件在 32 画布组合：block 放对象 → 世界坐标元件放亮紫特征 → 正屏符号放动作。
3. 导出透明 PNG 自检后，合成白底转 **32×32 24 位 BMP（3126B）**。
4. 100% 原尺寸视觉检查；替换 `DeployResources/startup/ikun_<repo>.bmp`，不改菜单注册项。
5. 跑 `ci/check_consistency.py`；若整体改风格/改校验规则，按 §11 写对抗审查报告并申请回写权威规范 §4.1。
