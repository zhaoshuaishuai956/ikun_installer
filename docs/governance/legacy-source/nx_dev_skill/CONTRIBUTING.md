# 维护要求（同步协议）

> **本文件（维护协议本身）+ `scripts/`、`.env.example` 只存在于私有仓库 `nx_dev_skill`，不进公开仓库 `nx_dev_handbook`。**
> 但**坑账内容**两仓一致：登记新坑时，**同一条坑会同时进私有仓和公开仓**（脚本默认行为）。
> 即——"怎么维护"（协议/脚本）私有；"维护出的知识"（含每一条坑）公开同步。

本知识库的价值 = **一个坑在被解决的当下被记录，从此不再重犯**。文档会腐烂，靠的就是这条协议被每个会话执行。

---

## 出任何问题，先跑 doctor（强健性）

新机器/新用户遇到**环境、目录、仓库、网络**任何未知问题，第一件事：

```powershell
pwsh -File scripts/doctor.ps1
```

它逐项体检并**自愈**：能自动修的直接修（自动发现/克隆公开仓、认领 remote、自签证书豁免、非快进自动 rebase），修不了的给出**确切的下一步命令**。幂等，可反复跑。设计与边界：

- **目录/发现类**（公开仓在哪、目录改名、坑账改名/重编号）→ 全自动：`add-pitfall.ps1` 运行时探测仓库根、按关键词动态定位分类标题、多策略发现公开仓、找不到就自动克隆。
- **网络类**（自签证书、非快进、离线）→ 自动：自签跳过校验、非快进自动 `pull --rebase` 重试、离线时**只本地提交不丢数据**，联网后 `git push` 即可。
- **凭证类**（`GITEA_*` 未设 / token 过期）→ 无法凭空生成，doctor 给出设置/续期的确切命令与 URL。
- **工具未装**（VS / NX 是付费授权软件）→ 无法自动安装，doctor 精确告知装什么、勾哪个工作负载。

> 这几个脚本（`doctor.ps1`、`skill-env.ps1`、`add-pitfall.ps1`）都是维护工具，**只在私有仓**。

## 什么时候登记

**解决了一个新的「共性坑」就登记**——指**跨工程复现**的编码 / 控件 / 链接 / API / 几何算法 / 流程类问题。

**不登记**：某工程一次性的细节（写到该工程自己的开发文档里）、还没真正验证的猜测。

## 怎么登记（二选一）

### 方式 A：脚本一键（推荐）

在本仓库根目录：

```powershell
pwsh -File scripts/add-pitfall.ps1 `
  -Category 控件读值 `
  -Phenomenon "运行时抛『属性类型不正确』" `
  -Cause "枚举控件用 GetInteger 读值，类型不匹配" `
  -Fix "改用 GetEnum(\"Value\") 取 int 索引"
```

**默认不自动提交——先弹建议，人工确认后才写入+提交+推送。** 两步：

1. **上面这条命令（不带 -Commit）= 只弹建议**：算出要加的条目、落在哪个小节，打印出来，**不改任何文件、不提交**。
   - 在真人终端里跑，会追加一句 `[y/N]` 确认，回答 `y` 才执行；
   - 被 agent/管道非交互调用时，只打印建议就退出——交给人工确认。
2. **人工确认无误后**，在同一条命令末尾加 `-Commit`，才真正执行（**一条命令同步两仓**）：
   - 把 `- **现象** → 根因 → 解法` 追加到 [`03-踩坑总账.md`](03-踩坑总账.md) 对应分类末尾 → `git commit` → `git push`（**私有仓**）；
   - 再把**同一条坑**（知识文件 01/02/03/04 + templates）同步到公开仓 `nx_dev_handbook`，用相同提交主题 commit → `git push`（**公开仓**）。

`-Category` 必须是这 9 类之一：`中文编码`、`控件读值`、`保留字`、`链接库`、`API`、`几何算法`、`流程协作`、`CAM`、`模块专属`（前 7 跨模块共性，后 2 模块专属）。

常用开关：
- （默认，无开关）—— 只弹建议，不写不提交（agent 应走这条，把建议交用户确认）。
- `-Commit` / `-Yes` —— 人工确认：写入 + 提交 + 推送（跳过交互问询）。
- `-NoPush` —— 确认后只本地提交，不推送（也不同步公开仓）。
- `-NoMirror` —— 确认后只更新私有仓，不同步公开仓。

> 公开仓工作副本默认在私有仓同级目录 `../nx_dev_handbook`；找不到时脚本会**自动克隆**，克隆不成再告警跳过（私有仓不受影响）。位置可用 `$env:NX_HANDBOOK_DIR` 覆盖。

**登记后顺手补决策表**：若该坑有稳定的**报错关键字或现象**（LNK/C 编号、异常文本、可复述的界面表现），在 [`06-报错决策表.md`](06-报错决策表.md) 对应分类补一行（关键字 → 根因 → 修复动作 → 出处指回 03）。06 是 03 的**索引视图**，03 仍是唯一权威源；补的行随同一次提交推送（脚本按 `0*.md` 通配同步公开仓，06 会自动带上）。

### 方式 B：手动

1. 打开 [`03-踩坑总账.md`](03-踩坑总账.md)，找到对应分类，**在该分类末尾**加一行：`- **现象** → 根因 → **解法**`。
2. 提交（格式见 [gitea-for-ai 的 AGENTS.md](/zhaoshen/gitea-for-ai)）：
   ```
   docs(pitfall): <一句话坑名>
   ```
   带 `Co-Authored-By` / `Agent` / `Device` trailers，然后 `git push`。

## 公开仓库（nx_dev_handbook）怎么处理

- 公开仓 = 本仓库的**知识镜像**：`README.md`、`01`/`02`/`03`/`04`、`templates/`、知识版 `AGENTS.md`、公开版 `LICENSE`。
- 公开仓**不含**本文件、`scripts/`、`.env.example`（"怎么维护"私有）。
- **坑账内容默认双仓同步**：`add-pitfall.ps1` 每次登记都会把同一条坑一并推到公开仓（脚本默认行为，加 `-NoMirror` 才跳过）。
- **同步方向**：私有仓是权威源，公开仓的知识由脚本从私有仓单向同步过去；不要直接在公开仓改坑账。

## 同步方向（避免多源漂移）

- 本仓库 [`03-踩坑总账.md`](03-踩坑总账.md) 是**权威源**。
- 公开仓 `nx_dev_handbook`、以及工作区另存的本地速查文档，都以本仓库为准、保持一致。

## 文件编码约定

- **所有 `.ps1` 一律存 UTF-8 with BOM**——无 BOM 时 Windows PowerShell 5.1 按系统 ANSI 代码页（中文机=GBK）解码，中文注释/字符串乱码甚至解析错误（全新 Windows 默认只有 5.1、没有 pwsh 7）。
- md / cpp / hpp / dlx 用 **UTF-8 无 BOM**（C++ 靠编译开关 `/utf-8` 正确解码，见 [`01`](01-环境与要求.md) §4）。

工作区的 AI 指令文件（`CLAUDE.md` / `AGENTS.md`）与记忆已登记「解决新共性坑 → 同步到本仓库」。若你是接手 NX 二次开发的会话，解决共性坑后**主动执行本协议**，这是本知识库存活的唯一方式。
