# NX 二次开发 Skill

> Siemens **NX 1847** 二次开发（NXOpen / UFUN，**全模块**：建模 / CAM / 装配 / 制图 / PMI / 钣金 …；界面用 Block Styler）的**单一可信知识库**。
> 目标：让任意一个全新的 AI 会话（或人），从零做到一个**能在 NX 里加载运行的插件**，且**不重蹈任何已知的坑**。

本仓库是 NX 二次开发一路踩过的共性经验的**单一可信知识库**，自包含、不依赖任何私有记忆或特定机器路径。任何接手 NX 开发的会话，**先读本仓库再动手**，可少走绝大部分弯路。不管做建模、CAM 还是其它模块，dll 骨架/编译/加载这条主干完全一致，差异只在调用的 API 与追加的链接库。

## 🚀 新手引导（零基础 · 通用 agent 版）

> 面向**完全没碰过 AI 编程**的新手。核心思路：**用任意一个能读写本地文件、能执行命令行的编程 agent**（Claude Code / Cursor / Cline / Windsurf / reasonix … 都行），把本知识库指给它，让它自己装环境、拷模板、编译、按坑账排错。**你只手动做少量事，其余复制提示词丢给 agent 自己做。**

### 一、你手动做这几件事

1. **准备一个编程 agent**：任选一个你跑得起来、能读写本地文件、能执行命令行的 agent，按各自官网说明配好它需要的 API key、能正常对话即可。常见：
   - **Claude Code**（CLI / VS Code / JetBrains，**自带看图能力**）
   - **Cursor** / **Cline** / **Windsurf**（IDE 内置，多数**自带看图**）
   - **reasonix**（桌面版，DeepSeek 为大脑；DeepSeek 是**纯文本、不自带看图**，见第 3 步）
2. **装好 NX**：NX 是付费软件、agent 装不了；确认已装好（默认 `C:\Program Files\Siemens\NX 1847\`）或设好 `UGII_ROOT_DIR`。
3. **（可选）解决"看图"**：编译报错、NX 弹窗、图纸经常需要 agent 看截图——
   - 你的 agent **自带视觉**（Claude Code / Cursor 等绝大多数）→ **无需任何配置**，需要它看图时直接把截图贴给它 / 拖进对话即可，本节到此为止。
   - 你的 agent 是**纯文本模型、看不了图**（如 reasonix 里的 DeepSeek）→ 按文末[附录：给没有原生视觉的 agent 外挂眼睛](#附录给没有原生视觉的-agent-外挂眼睛可选) 配一个视觉 MCP（用免费的 GLM-4V-Flash）。

> 各家 API key 是你的机密，存好、别外传、别截图。

### 二、让 agent 自己把环境配齐 —— 复制这段提示词

把下面**整段一键复制**到你的 agent 会话发送。它会自己：克隆知识库、**把编译 NX 插件需要的整条环境检查好并自动装齐（含 Visual Studio 的 C++ 工具集、Python 等）并用样例试编一个 dll 验证**。这样你真正跑用例时，不会被"缺 VS/缺编译器/缺某个库"这类超出你知识范围的问题卡住。

```text
你是我的一次性配置助手。我在 Windows，只会用 NX、不懂编程。请按顺序把“能编译 NX 插件的完整环境”配好；每步先说要做什么再执行，需要我批准或弹权限确认(UAC)时提示我，任一步失败就停下说明原因、不要跳过：

1) 确保 git 可用；没有就 winget install --id Git.Git -e --accept-source-agreements --accept-package-agreements 装上。
2) 在当前工作目录克隆知识库：git clone https://gt.h.zss.fan:2233/zhaoshen/nx_dev_handbook.git （公网可访问；自签名证书，报 SSL/证书错误就改用 git -c http.sslVerify=false clone <同一地址> 重试；仍失败问我要地址）。
3) 【关键·先把编译环境备齐】运行知识库自带的一键环境脚本，它会把“编译一个 NX 插件需要的整条环境”检查好并自动装齐（Python、Visual Studio 的 C++ 工具集、Windows SDK 等），最后用样例真编译一个 dll 来验证：
     pwsh -File nx_dev_handbook/templates/setup-nx-dev-env.ps1
   装 VS 是大文件、会弹权限确认，请让我点『是』。若它报“没找到 NX SDK”，提醒我确认 NX 已装好或设 UGII_ROOT_DIR（NX 是付费软件、装不了）。**必须等它显示“✅ 环境就绪：已成功编译出测试 dll”这步才算过**；没过就先解决它列出的项（VS/Python 刚装完可能要新开一个终端再跑一次）。
4) 完成后简单告诉我：知识库克隆在哪个目录、测试 dll 是否编译通过、以及**保留的测试 dll 的完整路径**（在知识库根下 _env_selftest\ 里，dll 和 dlx 同目录）——我会到 NX 里按 Ctrl+U 选它试加载，弹出对话框就说明全链路 OK。
```

**这一步你要做的只有**：中途点几下"允许/是"。完事。

### 三、开始干活 —— 再复制这段

配好后，在 `nx_dev_handbook` 目录的 agent 会话里发送：

```text
先读本目录 05-执行协议.md，并在本次及以后所有 NX 开发任务里全程严格执行它——特别是：需求确认卡未经我确认前不写任何代码；只从 templates/ 拷贝改写、不从零手写；编译前过一遍自查表并逐条打勾；报错先抄关键字查 06-报错决策表.md，同一报错最多修 2 次，修不好就停下问我。流程拿不准时照 07-完整范例.md 的样子做。然后读 03-踩坑总账.md 的分类标题和 01-环境与要求.md 的预检清单。我的第一个需求：用 templates/create_cuboid.* 模板做一个最简单的 Block Styler 对话框插件（无内部按钮，用 NX 自带的[确定]/[应用]创建长方体），用 build.ps1 编译成 dll。需要你看报错截图时我会把图发给你（若你没有看图能力，就用 analyze_image 工具看，我会给图片路径）。
```

**成功标志**：目录里出现 `xxx.dll` → 按 [`02-标准流程.md`](02-标准流程.md) 在 NX 里 **Ctrl+U** 加载弹出对话框。

### 省钱与安全（一句话）

各家 API 后台都设**消费上限**（视觉用的 GLM-4V-Flash 免费）；所有 key 只待在 agent 各自的密钥/环境配置里（本库 `.gitignore` 已排除 `.env`），别外传、别提交进 git。本引导写于 **2026-07**，各 agent 的安装与配置以其官网为准。

### 附录：给没有原生视觉的 agent 外挂眼睛（可选）

> 只有当你的 agent 是**纯文本模型、看不了图**（如 reasonix 里的 DeepSeek）时才需要本节。自带视觉的 agent（Claude Code / Cursor …）跳过——直接把截图贴/拖给它即可。

原理（第一性原理）：不去改一个可能不存在的"默认视觉模型"开关，而是用**几乎所有 agent 都支持的 MCP**，给纯文本模型外挂一个 `analyze_image` 工具——工具内部调**免费的 GLM-4V-Flash** 看图、只把**文字结论**返回给模型。图片只经过本进程，模型只处理文字 + 工具调用。真能跑，换后端只改一行。现成服务器、装法与各家（reasonix / Claude Code …）配置示例见 [`templates/vision-mcp/`](templates/vision-mcp/)。

你要额外做的：
1. **注册智谱**拿 key（GLM-4V-Flash 免费）：[open.bigmodel.cn](https://open.bigmodel.cn)，注册 + 实名认证。
2. 按 [`templates/vision-mcp/README.md`](templates/vision-mcp/README.md) 把 `vision_server.py` 作为一个 MCP 服务器接到你的 agent，把 `ZHIPU_API_KEY` 放进 agent 的密钥/环境配置（**别写进任何会被 git 提交的文件**）。
3. 接好后，需要看图时对 agent 说："用 analyze_image 看一下 `<图片绝对路径>`"。

## 这是怎么设计出来的（第一性原理）

一个 NX 二次开发知识库的不可再分目的，是把「从零到可加载 dll」这条路径上的**确定性步骤**和**非显然的坑**固化下来。价值的原子单位是：**一个坑在被解决的当下被记录，从此不再重犯。** 据此先拆成 5 个**知识**模块：

| 模块 | 文件 | 回答的问题 |
|---|---|---|
| **要求** | [`01-环境与要求.md`](01-环境与要求.md) | 装了什么、在哪、链哪些库、用什么编译开关 |
| **步骤** | [`02-标准流程.md`](02-标准流程.md) | 零 → 可加载 dll 的确定性流程，每步带命令 |
| **问题** | [`03-踩坑总账.md`](03-踩坑总账.md) | 每条坑：现象 → 根因 → 解法，分 9 类（7 跨模块共性 + CAM + 其它模块） |
| **速查** | [`04-控件与读值速查.md`](04-控件与读值速查.md) | 控件读值对照表、dlx 片段、UF 建模函数、CAM / 各模块入口 |
| **模板** | [`templates/`](templates/) | 可直接拷贝改名的 cpp/hpp/dlx/build.ps1，已实测编译运行通过 |

知识解决「不知道」；但模型（尤其轻量模型）还会「知道却做不对」——理解错需求就开写、脱离模板自由发挥出低级 bug、报错后瞎猜乱改。为此再加 3 个**纪律**模块，把对模型智力的要求降到「查表 + 照做 + 机器验证」：

| 模块 | 文件 | 治什么病 |
|---|---|---|
| **协议** | [`05-执行协议.md`](05-执行协议.md) | 八条铁律 + 带关卡的状态机：需求确认卡（治理解错需求）、只拷模板最小改写 + 编译前自查表（治代码低级错）、同一报错限修 2 次（治死循环） |
| **决策表** | [`06-报错决策表.md`](06-报错决策表.md) | 报错关键字 → 根因 → 修复动作，把排错降维成字符串匹配（03 的索引视图） |
| **范例** | [`07-完整范例.md`](07-完整范例.md) | 一次任务从需求卡到交付的全程示范剧本，拿不准就照抄 |
| **子项目规范** | [`08-子项目开发规范.md`](08-子项目开发规范.md) | 命名规范(英文snake_case+中文名) · 仓库结构 · 并入爱坤工具箱流程 · 自动打包CI · 新插件强制问询政策 |

## 快速上手

0. **全程遵守** [`05-执行协议.md`](05-执行协议.md)：需求确认卡 → 拷模板最小改写 → 编译前自查 → 机器验证；报错查 [`06-报错决策表.md`](06-报错决策表.md)；拿不准照 [`07-完整范例.md`](07-完整范例.md) 做。
1. **先读** [`03-踩坑总账.md`](03-踩坑总账.md) 的全部分类标题 + [`01-环境与要求.md`](01-环境与要求.md) 的预检清单。
2. 按 [`02-标准流程.md`](02-标准流程.md) 走：厘清需求 → 拷模板改写 → `build.ps1` 编译 → `dumpbin` 验证 → NX 里 **Ctrl+U** 加载。
3. 写控件 / 读值 / 建模时，随手翻 [`04-控件与读值速查.md`](04-控件与读值速查.md)。

## 适用边界

- ✅ NX/UG **全模块**二次开发：建模、CAM（工序/刀路/后处理）、装配、制图、PMI、钣金；对话框界面（Block Styler）、加改控件、编译/链接/运行排错。
- ❌ 不涉及写代码的纯 NX 操作问题；其它 CAD 软件。

更复杂的官方示例（对象选择 / 预览等）：NX 安装目录下 `UGOPEN\SampleNXOpenApplications\C++\BlockStyler\`（默认安装路径 `C:\Program Files\Siemens\NX 1847\`）。
