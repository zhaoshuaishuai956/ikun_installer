## 1. 命名规范（L3 §3）

### 1.1 英文名「四同」（L3 §3.1，强制）

**仓库名 = 本地目录名 = 工程/dll 基名 = 插件 id**，四者逐字相同：

- 全小写 `snake_case`、纯 ASCII（`a-z 0-9 _`）、≤ 28 字符；
- 结构 `<对象>_<动作>` 或 `<对象>_<特征>`，见名知义；
- 禁用 `nx_` 前缀、`test_/tmp_/new_/v2_` 临时前缀、产品编号/客户代号；
- dll/dlx/dat 文件名必须等于仓库名，菜单 `ACTIONS` 引用它。

> 存量债务：`MultiEntityNester` 驼峰不合规，改名计划见 L3 §3.3 / 迁移项 M1（需开发机重编译 dll，延后执行）。

### 1.2 中文名两级（L3 §3.2，修订自「正好 4 个汉字」）

- 全称 `name_cn`：恰好 4 个汉字，不带「爱坤」「工具箱」前缀，唯一、见名知义；
- 图标名 `icon_cn`：≤ 2 个汉字；
- 菜单 `LABEL` 必须逐字等于 `plugin.meta` 的 `name_cn`（L3 §8.2 / gate G5）。

### 1.3 dll 名即工程名（同 L3 §3.1）

改英文名 = 改 dll 名，须同步改菜单 `ACTIONS`/`BITMAP` 引用并**重新编译**（L3 §3.3 四阶段）。

## 2. 仓库标准结构（L3 §5）

```
<plugin_name>/
  <plugin_name>.cpp / .hpp / .dlx    # 源码+界面（从 templates/ 拷贝改写，禁止从零手写）
  build.ps1                          # 编译脚本（模板；机器判据：exit 0 + dumpbin 双导出）
  plugin.meta                        # name_cn / icon_cn / category / in_ikun（L3 §4.2 白名单）
  ikun-deploy.txt                    # 可选；每行一个 glob，禁止含 /（扁平部署）
  README.md                          # What/Why/Run/Test + 「验收标准」小节
  CHANGELOG.md                       # 强制；格式见 L3 §6.3（并入爱坤的仓尤其强制）
  LICENSE                            # 统一 MIT
  .gitignore                         # 必须覆盖 L3 §7.4 禁止入库物 + .env/token
  .gitattributes                     # 行尾规则；.men/.rtb/.tbr 标 binary
  .gitea/workflows/notify-installer.yml  # 仅 in_ikun=true 的仓（从权威模板复制）
```

校验：`verify-repo.ps1`（ikun_dev_standard 仓库）扫描真值表；并入仓缺 CHANGELOG/plugin.meta/LICENSE 标红，未并入仓标黄（L3 §5）。

## 3. 版本与变更记录（L3 §6）

- 插件版本权威源 = `CHANGELOG.md` 版本段头 `## vX.Y.Z (YYYY-MM-DD)`（三段式）；
- 允许顶部 `## Unreleased` 累积（≤ 20 条，超出折叠为版本段）；
- 每次更新制品（dll/dlx/dat）必须同步新增 CHANGELOG 条目（gate G4，阶段一警告+开 Issue，阶段二失败）；
- 条目 `- **类型**: 说明`，类型 ∈ 新增/修复/优化/变更，**写用户看得懂的话**。

## 4. 并入爱坤工具箱（L3 §8）

新建 NX 插件时**必须先问用户**「是否并入爱坤工具箱」（L3 §8.1，强制问询）：

- 是 → 三步接入（L3 §8.2，同一提交完成）：① `plugins.json` 登记 ② 菜单/ribbon 追加 BUTTON 块
  （GBK 编码，LABEL=name_cn，BITMAP=`ikun_<英文名>.bmp`）③ 复制 notify-installer.yml 权威模板
  （仅允许定制 `paths` 列表并注释声明）；
- 否 → 仅建仓，`plugin.meta` 写 `in_ikun=false`；
- 无论并入与否，**都必须在 registry.json 登记**（ikun_dev_standard 仓库，L3 附录 A 机器形态）。

## 5. 打包与发布（L3 §7/§9）

- 制品（dll/dlx/dat）与源码同一提交提交，注明编译环境；制品变更必须走 PR + D 类审查（L3 §12.3）；
- CI（rock5t）按 plugins.json 收集 → gate G1–G8 校验 → 交叉编译 win-x64 单文件 → 更新滚动 Release `latest`；
- 发布说明由 CHANGELOG 增量提取（每插件 ≤8 条）；Release name 固定四段 `爱坤工具箱 vX.Y.Z.W`；
- 更新链契约见 L3 §9.3（版本只增不减、fail-closed 校验、sha256 第二道校验、代码签名 M13）。
