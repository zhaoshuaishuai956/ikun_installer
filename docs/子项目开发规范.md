# 08 · 子项目开发规范（NX 插件工程标准）

> 本工作区所有 NX 二次开发插件（子项目）统一遵循本规范。目的：命名一致、结构一致、
> 可被爱坤工具箱自动打包。新建插件、接手插件、改名对齐都以本文为准。

---

## 1. 命名规范（英文 + 中文，强制）

### 1.1 英文名——"同名三位一体"
一个插件的 **仓库名 = 本地目录名 = 工程/dll 基名 = 插件 id**，四者完全相同：

- 全小写 `snake_case`，ASCII，只用 `a-z 0-9 _`；不用连字符、空格、大写、驼峰。
- 结构 `<对象>_<动作>` 或 `<对象>_<特征>`，见名知义：`ejector_layout`、`block_boss_layout`、`riser_base_fillet`。
- 长度 ≤ 28 字符；不带产品编号/客户代号（如 `_p1002`）——那类信息写进 README，不进名字。
- 不用 `nx_` 泛前缀（在 NX 工作区里冗余）、不用 `test_/tmp_/new_/v2_` 等临时前缀。

> 驼峰命名（如 `MultiEntityNester`）为**不合规**，须改为 `multi_entity_nester`。

### 1.2 中文显示名——两级
每个插件定义两个中文名，写在仓库根 `plugin.meta`（见 §2）：

- **全称**（README/更新说明用）：4–10 字准确描述，如「多实体二维排样」「顶针快速布局」。
- **图标名**（爱坤工具箱按钮/Ribbon 用）：≤ 2 个汉字，如「排样」「顶针」「刻字」「PMI」。

### 1.3 dll 名即工程名
dll 基名必须等于工程英文名（`multi_entity_nester.dll`）。改英文名 = 改 dll 名，
须同步改 NX 菜单 `custom.men`/`.tbr`/`.rtb` 里的 `ACTIONS`/`BITMAP` 引用并**重新编译**。

## 2. 仓库标准结构

```
<plugin_name>/
  <plugin_name>.cpp / .hpp / .dlx     # 源码 + 界面(见 02-标准流程)
  build.ps1                            # 编译脚本(模板)
  plugin.meta                          # 元数据(中文名/图标名/分类) —— 新增, 见下
  ikun-deploy.txt                      # 可选: 打包收集清单(缺省 *.dll *.dlx *.dat)
  README.md                            # What/Why/Run/Test
  CHANGELOG.md                         # 版本历史(## vX.Y.Z (YYYY-MM-DD))
  .gitignore  .gitattributes           # LFS 只track *.prt/*.bmp/*.ico 等; dll/dlx/dat 走普通对象
  .gitea/workflows/notify-installer.yml # 若已并入爱坤: 触发重新打包
```

`plugin.meta`（UTF-8，`key=value`）示例：
```
name_cn=多实体二维排样
icon_cn=排样
category=建模
in_ikun=true
```

## 3. Gitea 托管

- 仓库名 = 目录名（§1.1）；默认 **私有**（建仓后 PATCH 设 private，见 [[gitea-create-defaults-public]]）。
- 提交遵循 Conventional Commits + `Co-Authored-By`/`Agent`/`Device`（见工作区 gitea-workflow）。
- dll/dlx/dat 作为普通 git 对象提交（非 LFS），保证 CI 能 `git clone` 直接拿到。

## 4. 部署清单 `ikun-deploy.txt`（通用打包）

爱坤工具箱 CI 收集插件资源时的规则：
- 有本文件：按每行一个 glob 收集（`#` 注释、空行忽略），如 `*.dll`/`*.dlx`/`*.dat`/`*.cfg`。
- 无本文件：默认收集 `*.dll *.dlx *.dat`。
- 文件**扁平**部署到安装器 `application/`（与 NX 从 dll 同目录读数据一致）；暂不支持子目录树。

## 5. 并入爱坤工具箱的流程

**新建 NX 插件时，必须询问用户"是否并入爱坤工具箱"**（见 §7 政策）。若并入：

1. 在 `ikun_installer` 仓库 `plugins.json` 登记：`{ "repo": "<name>", "ref": "master", "icon": "<图标名>" }`。
2. 在 `ikun_installer` 的 `DeployResources/startup/` 加菜单/图标条目：
   - `custom.men`：加 BUTTON/LABEL/BITMAP/ACTIONS（**GBK/ANSI 编码**，用 `Encoding 936` 读写）。
   - `ikun.rtb`：加 BUTTON（Ribbon 选项卡直显，见 [[ikun-installer-packaging]]）。
   - 图标 `ikun_<name>.bmp` 若缺，CI 会用图标名自动生成（`ci/gen-icons.sh`）。
3. 在本插件仓库加 `.gitea/workflows/notify-installer.yml`（复制现有子项目的即可）。

之后：改插件 `push` → 自动触发 CI 在 rock5t 打包 → 更新 Release。

## 6. 自动化构建集成（rock5t CI）

- Runner：rock5t 的 `gitea-runner` 容器，标签 `dotnet`。
- 链路：子项目 push(dll/dlx/dat) → `notify-installer.yml` dispatch → `ikun_installer/pack.yml`
  → 收集资源 + 生成缺失图标 + 交叉编译 win-x64 单文件 → 更新 Release（版本号 = csproj Version + 构建号）。
- 详见 `ikun_installer` 仓库 README「自动打包」节与 [[ikun-installer-packaging]]。

## 7. 新插件强制问询政策（3a）

创建/初始化任何新的 NX 插件工程时，**AI/开发者必须先问用户**：

> 「这个插件是否并入『爱坤工具箱』作为子项目？」

- **是** → 按 §5 接入（plugins.json + 菜单/图标 + notify workflow），并在 `plugin.meta` 写 `in_ikun=true`。
- **否** → 仅按 §2 建独立仓库，`in_ikun=false`；不加 notify workflow。
- 不确定 → 默认**先问**，不擅自并入或排除。
